## Технические нюансы, добавившиеся за сессию

1. **Специфичность `--domain-text` — теперь стандартный приём во всех
   контурных скинах.** Groovy и graffiti независимо упёрлись в одну и
   ту же проблему (светлый текст на светлом акценте не проходит
   контраст) и решили её одинаково: `--domain-text` по умолчанию на
   одно значение, override на конкретном `[data-domain]` для
   единственного цвета, который не проходит. Если добавится пятый скин
   с доменными кнопками — сразу считать контраст, не доверять глазу.
2. **CSS-слот под картинку без самой картинки — открытая дыра, если в
   нём уже есть `padding-top`/`padding-bottom` под размер
   иллюстрации.** Разметка и картинки должны попадать в репозиторий
   ОДНИМ изменением. Дважды наступили в эту сессию (сначала на pixel,
   вынес урок, применил сразу и на graffiti).
3. **`file://` не эмулирует бэкенд** — фронтенд рисуется, но любой
   fetch к относительному `/api/...` зависает на таймауте, а не падает
   сразу. Смотреть интерактив только с поднятым бэкендом.
4. Старые грабли (деплой только через `scripts/deploy.sh`,
   scratch-проверка миграций, `pydantic-settings extra="forbid"`,
   `.claude/settings*.json` коммитит только владелец вручную, PATH для
   Node/Python не подхватывается в старой Bash-сессии) — без изменений.

## Что сделано в этой сессии

### 1. REST API дайджестов + форма на сайте (spec 015)

Закрыт последний невыполненный пункт из списка владельца. Пять
эндпоинтов в `app/api/digest.py`, схемы в `app/digest/schemas.py`
(домен был единственным без них), карточка «Дайджесты каналов» в `/ui`.

**Главное решение — про потерю постов.** `build_digest_text` двигает
водяной знак и коммитит его ДО отправки. Для фоновой джобы это
осознанный компромисс (записан в её докстринге), но для кнопки на сайте
он давал скверный сценарий: нажал, увидел ошибку, содержимое пропало
навсегда. Поэтому эндпоинт **всегда возвращает собранный текст**, а
доставку показывает отдельным полем `delivered`. Не доставили — сайт
показывает дайджест прямо на странице. Порядок «сначала отправить, потом
сдвинуть» переписывать не стали: это правка сервиса, которым пользуются
ещё бот и джоба, ради случая, который лечится одним полем в ответе.

- `app/telegram/notifier.py` — отправка владельцу из процесса API. Бот и
  API разные контейнеры, `context.bot` там недоступен, но `.env` общий,
  так что токен есть. `Bot` кэшируется по токену (как `get_ai_client`).
  Нет токена → `503`, а не тихий успех.
- Частота — `Literal["daily","weekly"]`, не свободная строка: опечатка
  `dayly` доехала бы до БД и молча отключила автоотправку.
- Удаления ТЕМЫ нет намеренно — его нет и в боте, переносить нечего.
- Тест «текст возвращается при сбое доставки» **проверен мутацией**.
- Миграций не потребовалось: таблицы из `014` уже на проде.

Попутно: `api()` в `/ui` больше не показывает сырой JSON в тостах —
`extractDetail` вытаскивает `detail`. Касается всех карточек.

**Клик по плашке задачи в календаре открывает её в редакторе.** Слушаем
всю карточку календаря, поэтому работает и в месячной сетке, и в панели
часов. Перетаскивание отделено флагом: после переноса задачи редактор не
открывается.

### 2. Иконки: переработан базовый набор, добавлены наборы под скины

Претензия владельца «несуразные, местами нечитаемые» разобрана: глифы
рисовались под 24px, а живут на 12–16px.

- Переработано 8 из 16: кольцо стало кольцом, у замка дужка с 1.3 до
  2.9u, монеты вместо «полумесяца» — монета со стопкой, у `repeat`
  стрелка пересекает кольцо (одна фигура вместо двух), у книги зазор
  3.2u, мишень различается формой а не альфой, плёнка заменена на «play»
  (перфорация исчезала первой), полка — книги на основании, ракета слита
  в один силуэт, у кубка убраны ручки.
- Нижняя граница поднята: `.rewards-label .icon-chip` был `1.25em`
  (глиф ~11.6px — самое мелкое место интерфейса), стал `1.45em`.
- **Пиксельный набор** хранится сеткой 12×12 (`PIXEL_GRID`), а не
  путями: так глифы физически не могут съехать с пиксельной сетки.

- **Контурный набор** `ICON_LINE` остался только у японского. Груви

- `glyphBody()` выбирает набор по активному скину; скин без своего

**Главный вывод сессии.** Три захода скин `groovy` не давал вида из
референса, и каждый раз казалось, что дело в мелочах: то декор наружу,
то специфичность, то пустота. Причина была не в стилях. Референс
получает композицию из ДРУГОЙ СТРУКТУРЫ страницы, а скин структуру не
меняет — он меняет цвет, шрифт, контур и картинки.

Отсюда правило на будущее: **если не сходится композиция — это не
задача скина.** Раскладку чиним один раз в базовой вёрстке, скины
остаются косметикой. Иначе каждый скин обрастает своим набором
костылей, и их становится четыре.

Что сделано:

- **Шапка**: лого, семь вкладок, чипы монет и серии, кнопка настроек.
  Спойлер «Настройки доступа» уехал из потока в панель поверх.
- **Вкладка — фильтр видимости, а не отдельная страница.** Карточка в
  DOM ровно одна: секция на вкладку потребовала бы дублировать разметку
  либо переносить узлы, а рендеры ищут элементы по id. Вкладки трогают
  только `hidden` и `grid-column`, ни один рендер переписывать не
  пришлось.
- **Мозаика 12 колонок**: визит 3 на два ряда, задачи 5, привычки 4;
  ниже цели/итоги/полка по 3; дайджесты 12.
- **Календарь ушёл на свою вкладку** — во всю ширину вверху он съедал
  экран и ломал композицию, а в референсе его нет вовсе. Страница стала
  1535px вместо трёх экранов.
- Ряды снова выравниваются по высоте. `align-items: start` убирал
  пустоту, но давал рваные низы — это и называлось «странная
  раскладка». Пустоту добирает иллюстрация.
- Счётчики в шапке дублируют ЗНАЧЕНИЕ, а не узел: на исходных
  `#coinsCount`/`#streakCount` висят анимация счёта и «поп».
- Ширина полосы 1100 -> 1560 для всех скинов.
- Из `groovy` вырезаны ВСЕ правила сетки.

Проверено, что обычный, японский и пиксельный скины получили ту же
мозаику — раскладка перестала зависеть от оформления.

### 3b. Скин `groovy` по дизайн-системе 003

Первая версия была переопределением токенов поверх обычной вёрстки:
палитра, скругления, шрифт. Вёрстка осталась панельной, и владелец
справедливо сказал, что вышла перекрашенная админка. Референс держится
не на цвете, а на трёх вещах, которых токенами не выразить: толстый
чернильный контур на каждой поверхности, иллюстрация в КАЖДОЙ карточке,
крупная типографика.

`designs/003-groovy-design-system.md` — система целиком. Что в вёрстке:

- сетка **12 колонок с разной шириной соседей** вместо `auto-fit`:
  календарь 12, визит/задачи/привычки по 4, цели/итоги/полка/дайджесты
  по 3. Одинаковая ширина у всех и есть «одинаковые карточки»;
- контур 4px у карточки, 3px у кнопок, полей, чипов, строк списка;
- тень — **сплошной чернильный сдвиг 5px без размытия**. Размытая тень
  это Material, она несовместима с контурным рисованием;
- заголовок карточки 26px (был 16), монеты 64px;
- чип иконки — скруглённый **квадрат**, залитый цветом домена: круг был
  приметой прошлой версии;
- приглушённый текст **тёплый коричневый, не серый** — серый протаскивал
  «админку» обратно даже при верной палитре;
- `data-domain` на каждой карточке (атрибут скин-независимый): по нему
  идёт цветовое кодирование и раскладка декора.

**24 картинки, 449 КБ** после сжатия. Три уровня: герой (пустые
состояния, ракета у целей, график у итогов), угловой декор (у соседей
РАЗНЫЙ — один цветок в каждом углу превратил бы приём в обои), волны по
низу задач и дайджестов. Микрозвёзды рисуются кодом, не картинками:
инлайновый SVG, позиции детерминированы индексом карточки, а не
`Math.random()` — иначе прыгали бы при каждой перерисовке (тот же довод,
что у «счастливых дней» в `app/rewards/coins.py`).

Анимации: подъём карточки на 5px, пружинный «поп» счётчиков, блик по
прогресс-бару, дрейф облаков 24-40с — медленно намеренно. Адаптив
декор **перестраивает, а не прячет**: `display:none` на украшениях — тот
самый приём, которым интерфейс на телефоне становится обратно панелью.

`avatar.png` и четыре бейджа сгенерированы, но НЕ подключены: под них в
интерфейсе нет мест (нет блока профиля и строки порогов). Лежат на
будущее — решение владельца не перегружать сейчас.

### 3b. Скин `japan` — сделан СТАРЫМ способом

Состаренная бумага, индиго и киноварь, острые углы, теней нет, шрифт —
системная Georgia (гравюрных с кириллицей практически нет, а лишние
30 КБ ради приблизительного попадания не стоят).

> **Образцом для новых скинов брать груви, а не японский.** Японский —
> это перекраска поверх обычной вёрстки, ровно та ошибка, за которую
> пришла критика. Его самого стоит однажды привести к системе 003.

Иллюстрации у обоих подключены как `background-image`, а НЕ `<img>`:
пока файла нет, фон просто не отрисуется — без битой иконки и ошибки в
консоли. Это же свойство позволяет верстать под картинки заранее.

## Как сжимать картинки скина

Генератор отдаёт файлы по ~1.5–3 МБ; в прод такое класть нельзя.
Обработка — обрезка по альфе, вписывание в целевой бокс, квантование
палитры с сохранением альфы (`FASTOCTREE` — единственный метод в PIL,
который переживает альфу; `MEDIANCUT` молча её теряет).

Что выяснилось на практике:

- **groovy**: палитра 200, масштаб 1.0 → 292 КБ. Ниже 128 цветов
  начинают полосить мягкие переходы в лепестках и облаках.
- **japan**: палитра 64, масштаб 0.75 → 228 КБ. Здесь вес держит НЕ
  палитра, а мелкая гравюрная штриховка: снижение цветов с 200 до 48
  дало всего 555→326 КБ, а уменьшение размера сразу втрое. Логика
  простая: на экране картинка 120px, исходник был 400px.

Оригиналы генератора лежат в `Файлы для дизайна стилей/` и **в гит не
идут** (49 МБ, добавлено в `.gitignore`). В репозитории только сжатые
версии в `lifeos-agent/app/web/static/skins/`.

## Технические нюансы, добавившиеся за сессию

1. **Ассеты скинов грузятся лениво самим браузером** — CSS ссылается на
   них только внутри `[data-skin="…"]`, поэтому человек на стандартном
   скине не скачивает ни груви, ни японский.
2. **`[hidden]` бессилен против авторского `display`** — старые грабли,
   теперь для `.digest-preview` правило написано сразу. Глобального
   `[hidden] { display: none }` в проекте по-прежнему нет; каждому новому
   элементу, который прячется атрибутом, нужно своё правило.
3. **Скины, меняющие режим, проверять в обоих системных темах.**
   `graffiti` будет первым таким (тёмные карточки, светлый текст) — ему
   понадобятся собственные `--card-bg`/`--text`, иначе у половины
   пользователей выйдет светлый текст на светлой карточке.
4. **Специфичность CSS съела три вечера — проверяйте её ПЕРВОЙ.** Три
   разных бага одной природы: правило скина проигрывало более весомому
   базовому и молча не применялось.
   - `.empty` (0,3,0) против `ul.item-list li` (0,3,2) — иллюстрации
     пустых состояний вообще не показывались, картинка обрезалась в
     полоску 53px;
   - `[data-domain="calendar"]` (0,3,0) против `.grid > .card` (0,4,0) —
     календарь получал span 4 вместо span 12;
   - клетка календаря брала `--radius-control`, у груви это таблетка
     999px, и номер дня уезжал за скругление: «.7» вместо «17».
   Симптом всегда одинаковый: правило написано, а в браузере его нет.
   Смотреть computed style, а не исходник.
5. **Псевдоэлемент с `z-index` выигрывает у обычных потомков.** Угловой
   декор с `z-index:1` накрывал заголовки шести карточек и кнопку: у
   детей `z-index: auto`, и позиционированный псевдоэлемент рисуется
   поверх. Лечится ПАРОЙ правил — декор на `z-index:0` И содержимое на
   `z-index:1`; одного первого мало.
6. **Сгенерированную волну нельзя тайлить `repeat-x`** — фазы на левом и
   правом крае не совпадают, на стыке излом. Растягиваем на ширину
   карточки: у волны нет «правильных» пропорций, растяжение незаметно.
7. **Проверять кликабельность только в видимой области.**
   `elementFromPoint` для точки за пределами окна возвращает пустоту, и
   это легко принять за перехваченный клик — потерял на этом время.
8. **Тестовый харнесс `/ui` требует `import app.main` до `create_all`** —
   иначе половина моделей не зарегистрирована и `/rewards` падает с
   `no such table: checkins`. Это дефект харнесса, не приложения;
   потерял на нём время.
9. **Печати-ханко и кандзи на японских картинках модель рисует сама** —
   проверить их без знания языка нельзя. Если понадобится точность,
   генерировать пустую рамку печати, а иероглиф ставить SVG.
10. Старые грабли (деплой только через `scripts/deploy.sh`,
   scratch-проверка миграций, `app/rewards/service.py` вызывает
   `coins.py` через модуль, heredoc с `\n` на Windows, кириллица в
   путях, алембик-ревизии ≤32 символов, pytest только из
   `lifeos-agent/`) — без изменений.

4. **Атрибут `hidden` бессилен против авторского `display`.** Диалог
   правки висел поверх страницы с самой загрузки именно поэтому: у

   прячется через `hidden`, нужно правило `[hidden] { display: none }`.
5. **pytest запускать только из `lifeos-agent/`.** Из корня репозитория

> **Перед обратным включением сделать счётчик минут на пользователя и
> лимит** — иначе расход виден только в счёте OpenRouter.

## Что решать в начале новой сессии

**Открытый вопрос — модель монетизации.** Он влияет на то, сколько из
«этапа 0» (см. `MULTIUSER.md`) вообще нужно делать, поэтому решать его
надо ДО кода.

Владелец в конце сессии предложил два варианта, оба разумные:

1. **Пока вообще не брать плату.** Тогда Telegram Stars, тарифы, чеки и
   налоговая часть отпадают целиком — остаются только изоляция данных и
   152-ФЗ (они нужны при любом раскладе, как только появляется чужой
   человек). Самый быстрый путь к «пустить 10–20 человек».
2. **Брать плату только за голосовой ввод.** Это неожиданно хорошо
   ложится на реальную экономику: по расчёту в `MULTIUSER.md` голос —
   ЕДИНСТВЕННАЯ статья, которая заметно стоит денег ($0.9–1.8 на юзера в
   месяц при 5–10 минутах в день), всё остальное (LLM-фолбэк, саммари
   дайджестов, embeddings) — центы. То есть платит тот, кто реально
   создаёт расход, а бесплатным остаётся всё, что почти ничего не стоит.
   Побочный плюс: тариф объясняется одной фразой, без «премиум-фич».

Что важно не упустить при обсуждении:

- Оплата цифровой услуги внутри бота — **только Telegram Stars** (проверено,
  см. источники в `MULTIUSER.md`). Даже «платим только за голос» — это Stars.
- Даже в бесплатном варианте нужен **счётчик минут голоса на пользователя**
  и лимит: без него один говорливый человек обнаружится только в счёте
  OpenRouter.
- Бесплатно ≠ без обязательств: 152-ФЗ, согласие в `/start` и удаление
  аккаунта нужны с первого же постороннего пользователя, платного или нет.

**После решения** — «этап 0» из `MULTIUSER.md` в том объёме, который
решение оставит. Порядок внутри этапа: таблица `users` → allowlist из БД
вместо `owner_telegram_user_id` → скоупинг 12 джоб по пользователям →
Mini App вместо общего API-токена для `/ui` (сейчас это дыра: юзер с
токеном подставит чужой ID и прочитает чужой дневник) → контрактный тест
на изоляцию → `/delete_me` → счётчики расхода.

## Технические нюансы этой сессии

1. **`pending_input` живёт в памяти процесса** (`context.user_data`), а
   не в таблице. Осознанно: это секундное «жду одно слово», ради него не
   нужны миграция и поход в БД на каждое сообщение (ADR-004). Плата —
   рестарт бота забывает ожидание, пользователь нажимает кнопку ещё раз.
   Дневниковая запись по-прежнему идёт через таблицу `pending_prompts`:
   она осмысленна и через час.
2. **`callback_data` — 64 БАЙТА на всю строку.** Имя дайджеста туда
   класть нельзя (кириллица + до 50 символов), поэтому в кнопках везде
   ездит числовой id, а имя достаётся из БД.
3. **Саммари дайджеста экранируется** перед отправкой: текст приходит от
   модели и из постов канала, угловые скобки сломали бы `parse_mode=HTML`
   всего сообщения.
4. **`callbacks.py` импортирует `JOURNAL_PROMPT` из `handlers.py`** —
   цикла нет (обратного импорта не существует), но если когда-нибудь
   `handlers` начнёт импортировать `callbacks`, эту константу надо будет
   вынести в отдельный модуль.
5. Старые грабли (деплой только через `scripts/deploy.sh`, scratch-проверка
   миграций, `app/rewards/service.py` вызывает `coins.py` через модуль,
   heredoc с `\n` на Windows, кириллица в путях, алембик-ревизии ≤32
   символов) — без изменений, см. историю ниже.

  `X-API-Token` (`app/api/deps.py`), пустой токен **закрывает** API, а
  не открывает — забытая настройка не должна снимать защиту.
- **Токен бота и SQL с личными данными утекали в логи контейнера** —
  `sql_echo` теперь выключен по умолчанию, `httpx`-логи бота приглушены.
  Токен бота был **перевыпущен** в @BotFather (старый успел засветиться).
- **Бот отвечал кому угодно** — добавлен `filters.User(owner)` на все
  хендлеры + проверка владельца в callback-обработчике (там же был
  IDOR: id брался прямо из `callback_data` без проверки, чей это id).
- Плюс: устойчивость к кривому `callback_data` (`add_error_handler`,
  `parse_callback` больше не роняет хендлер), CORS сужен, `/docs`
  выключен на проде.

### 3. Деплой теперь идёт из гита, а не из рабочей папки

Раньше `tar` паковал файлы прямо с ноутбука — гит в цепочке не
участвовал, три копии кода (ноутбук/GitHub/сервер) могли разъехаться
незаметно. Теперь:

```bash
lifeos-agent/scripts/deploy.sh          # деплой: archive HEAD -> rsync -> миграции -> рестарт
lifeos-agent/scripts/deploy.sh --check  # сверить прод/гит/локаль без деплоя
```

Три проверки перед выкаткой (любая роняет деплой): рабочая папка
чистая, `HEAD` запушен в `origin/main`, тесты зелёные. Прод пишет свой
коммит в `DEPLOYED_COMMIT`, который отдаётся в `/health` —
`curl https://lifeos-agent.ru/health` показывает `commit` без захода на
сервер.

**Используйте только этот скрипт для деплоя.** Старый способ (`tar` +
ручной `docker compose up -d --build` через ssh) больше не должен
применяться — он и есть тот источник рассинхрона, который чинили.

### 4. Живые баги, найденные лично вами на реальном использовании

Это не абстрактный код-ревью — каждый пункт всплыл из скриншотов бота
в реальном диалоге:

- **`/help` и напоминания проваливались в дневник**, если рядом был
  открыт вопрос "что снилось?" — перехват дневника случался раньше
  разбора команд. Починено дважды (сначала только `/`, потом до конца
  — любое слово-команда в начале сообщения).
- **Окно "свежести" pending-вопроса было 30 минут** — ответ на
  утренний вопрос, пришедший через 2ч26м, улетал в обычный разбор и
  создавал бессмысленную задачу. Слоты дня разнесены на 3.5-5 часов и
  каждый следующий перезаписывает вопрос сам — окно увеличено до 6
  часов, реальная его роль — не путать случайную команду через
  несколько ДНЕЙ с ответом на забытый вопрос.
- **Время съезжало на 3 часа** — `asyncpg` отдаёт `due_date` в UTC, а
  показывался он как есть. Задача создавалась верно, врал только
  текст — это хуже тихой ошибки, потому что подрывает доверие к боту.
  Добавлен перевод в местное время перед любым показом
  (`app/tasks/formatting.py::to_local`).
- **«напомни» всегда означало поиск по памяти** — самый тяжёлый баг:
  `напомни в 19:00 позвонить маме` не создавало вообще ничего, бот
  молча искал в памяти. Теперь при наличии времени/даты это задача.
- Не разбирались форматы времени: `в 19 00`, `в 9 утра`, `через пару
  часов`, `через полчаса`. День и время не совмещались (`завтра в
  19:00` давало сегодня в 19:00). Всё это починено, дата-парсер
  переписан на раздельный разбор дня и времени.
- Слово-обращение оставалось в названии: `напомни МНЕ...` → задача
  «мне запустить стиралку». Обращения (мне/пожалуйста/плиз) теперь
  снимаются вместе с командой.
- **Кнопка «🌐 Сайт» не появлялась** — ReplyKeyboardMarkup живёт на
  клиенте, пока его не заменят, а меню отправлялось только на
  `/start`. Добавлена `/menu`, и меню переотправляется с каждым
  ответом бота без inline-кнопок — новые кнопки появляются сами.

### 5. Производительность (AUDIT.md P-1, P-2, P-4, P-6 — закрыты)

- N+1 по стрикам привычек (каждый показ списка = запрос на каждую
  привычку) — заменено на один запрос `IN(...)` + пакетные методы
  (`app/habits/streaks.py`, `HabitService.*_bulk`).
- Поиск по памяти/задачам/привычкам грузил всё в Python — заменено на
  `ILIKE` в БД с ручным экранированием `%`/`_`.
- Новое TCP+TLS соединение на каждый вызов OpenRouter — один
  `httpx.AsyncClient` на процесс, `get_ai_client()` кэширует один
  `AIClient`.
- Недостающие индексы: `tasks(telegram_user_id, status)`, частичные
  индексы под джобы напоминаний и доливки embedding.

Попутная находка: SQLite в тестах не умеет регистронезависимо сравнивать
кириллицу (встроенный `lower()` там ASCII-only), а весь проект на
русском. Проверено вживую на боевом Postgres, что там всё работает
(`SELECT 'Молоко' ILIKE '%молоко%'` → true) — баг был только в тестовой
среде. `tests/support.py::sqlite_engine()` регистрирует Unicode-aware
`lower()` на тестовый движок.

**Не начато**: P-3 (семантический поиск не масштабируется без
pgvector — не срочно, актуально после ~1000 записей памяти), B-6/B-7/B-8
(границы слов в парсере, мелочи разбора дат).

### 6. Редизайн бота

- **Списки** (задачи/привычки/цели/полка) — содержимое переехало из
  подписей кнопок (обрезались по 45 символов) в текст сообщения.
  Полное название, срок словами, цветной кружок срочности
  (🔴 просрочено/🟠 сегодня/🟡 завтра/⚪ позже), кнопки — короткие и
  нумерованные.
- **Брифинг и итоги дня** — дата словами в шапке, блок «Главное на
  сегодня», разделы «Дальше»/«Просрочено (N)», полоски прогресса,
  живая финальная фраза вместо сухих цифр.
- **Ответы на команды** — короче и с интонацией («✅ «X» — сделано!»
  вместо «Готово: «X» отмечена выполненной.»).

Первая строка ответа о созданной задаче **намеренно** осталась в
прежнем виде — по ней `handlers.py` регуляркой узнаёт «задача создана»
и цепляет быстрые кнопки. Хрупкая связка, помечена в коде и в
`AUDIT.md` (A-4) как кандидат на структурированный результат вместо
строки — не трогать формулировку первой строки без этого рефакторинга.

### 7. Редизайн `/ui`

- Настройки под спойлер, карточки с тенями, точки срочности, те же
  человеческие даты, что у бота.
- Фон: два размытых пятна медленно дрейфуют (декоративно, отключается
  через `prefers-reduced-motion`).
- Появление карточек/строк при загрузке, вспышка при «выполнить»,
  «заливка» прогресс-баров, счётчик цифр для статистики.
- **Мини-игра «🪙 Ежедневный визит»** — новый бэкенд-домен
  `app/rewards/` (модели/репозиторий/сервис по стандартному шаблону
  проекта). Ежедневный чек-ин даёт монеты (растущий бонус за серию,
  капается на 15-м дне), ~15% дней «счастливые» (x2, детерминировано
  хешем `(user, день)`, не настоящий `random()` — иначе сумма монет
  «плавала» бы при каждой перезагрузке). Восемь достижений считаются
  на фронте из уже загруженных данных (без отдельного бэкенд-сервиса).
  Пять тем оформления открываются порогами монет, красят всю страницу
  через CSS-переменные, хранятся в `localStorage` (косметика, не
  данные). Звания (🌱→🚀→⭐→👑→🏆), конфетти на юбилеях серии.

Ключевая деталь для будущих правок `app/rewards/`: `service.py`
обращается к `coins.is_lucky_day`/`coins.total_coins` **через модуль**
(`from app.rewards import coins`), а не через `from ... import
is_lucky_day` — при прямом импорте имени тесты патчили бы две
независимые ссылки на одну функцию и получали рассинхрон между тем,
что видит `_status()`, и тем, что использует `total_coins()` внутри
себя. Если добавляете новый вызов чего-то из `coins.py` в `service.py`
— вызывайте через `coins.имя_функции(...)`, не через прямой импорт.

## Технические нюансы, которые стоит помнить

1. **Деплой — только `scripts/deploy.sh`**, не руками через `tar`/`ssh`
   (см. раздел 3 выше).
2. **Перед любой миграцией — scratch-проверка на сервере** (см. раздел
   "Что сделать в начале новой сессии").
3. **`app/rewards/service.py` вызывает `coins.py` через модуль**, не
   прямым импортом имени (см. раздел 7 выше) — важно при тестировании.
4. Heredoc-подстановка `\n` через Bash-инструмент на Windows иногда
   превращает escape-последовательность в настоящий перевод строки и
   рвёт Python-строковые литералы (`f"...\n..."` ломается на два
   физических файла). Если редактирование через `Edit`/`Write`
   недоступно и нужен heredoc — писать многострочный Python-скрипт во
   временный файл и запускать его, а не инлайнить в `python -c` через
   heredoc с `\n` внутри f-строк.
5. Старые грабли из прошлого HANDOFF (Bash+кириллица, SSH-ключи,
   Postgres volume-пароль, `JSON(none_as_null=True)`, uvicorn за
   прокси, алембик-ревизии ≤32 символов) остаются актуальными, см. ниже.

## Технические грабли (актуальны)

1. Windows + Bash-инструмент: `cd` в кириллический путь иногда
   спонтанно фейлится — повторить без `cd`.
2. SSH-ключ в веб-форме хостера — вставлять вручную одной строкой.
3. Postgres в Docker: `POSTGRES_PASSWORD` из `docker-compose.yml`
   применяется только при первой инициализации пустого volume.
4. `echo "x" >> .env` без финального переноса строки — значение
   приклеится к предыдущей строке.
5. JSON-колонки в SQLAlchemy: `JSON(none_as_null=True)`, если значение
   может быть `None` и по нему потом фильтруют `IS NULL`.
6. uvicorn за реверс-прокси: всегда `--proxy-headers
   --forwarded-allow-ips=*`.
7. Алембик: id ревизии ≤32 символов.
