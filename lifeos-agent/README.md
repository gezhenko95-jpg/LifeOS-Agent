# LifeOS Agent

Personal AI Chief of Staff - операционная система для управления жизнью.

## О проекте

LifeOS Agent — это персональный AI Chief of Staff, который помогает пользователю управлять жизнью, снижая когнитивную нагрузку. Это не просто чат-бот, а проактивный помощник для планирования, организации и анализа.

## Быстрый старт

### Установка зависимостей

```bash
pip install -e .
```

### Установка dev зависимостей

```bash
pip install -e ".[dev]"
```

### Запуск локально

1. Скопируйте `.env.example` в `.env` и настройте переменные окружения
2. Запустите базу данных:

```bash
docker-compose up -d db
```

3. Примените миграции:

```bash
alembic upgrade head
```

4. Запустите приложение:

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### Запуск в Docker

```bash
docker-compose up
```

Поднимет три контейнера: `db` (PostgreSQL), `api` (FastAPI) и `bot` (Telegram-бот, polling).

### Запуск Telegram-бота локально (без Docker)

1. Заполните `telegram_bot_token` в `.env` (токен из @BotFather).
2. Поднимите базу: `docker-compose up -d db` (либо локальный PostgreSQL).
3. Примените миграции: `alembic upgrade head`.
4. Запустите бота:

```bash
python -m app.telegram.runner
```

После `/start` под полем ввода появляется постоянное меню (📋 Задачи / 🔁 Привычки / 🎯 Цели / ❓ Помощь) — можно тапать вместо печати. Кроме него бот понимает обычные сообщения без команд:

- «Завтра купить молоко» — создать задачу с датой;
- «напомни через 10 минут позвонить» / «через 2 часа» / «в 18:30» — задача с точным временем — придёт отдельное напоминание (см. ниже);
- «покажи задачи» / «мои задачи» / `/tasks` — список активных задач с кнопками ✅/🗑 под каждой (тап вместо печати);
- «выполнил купить молоко» — отметить задачу выполненной (поиск по подстроке названия);
- «удали купить молоко» — удалить задачу;
- «привычки» / `/habits` — список привычек со стриком (🔥 дней подряд), тоже с кнопками;
- `/goals` — список целей с кнопками ➖10%/➕10%/✅ Готово/🗑 (заводятся всё ещё через REST `POST /goals` или `/ui`);
- «привычка чтение» — отметить привычку «чтение» выполненной сегодня
  (повторная отметка в тот же день не дублируется);
- «дневник: как прошёл день» (или «рефлексия: ...», «итоги дня: ...») —
  сохранить запись в долгосрочную память;
- `/help` — краткая справка.

Новые привычки заводятся через REST API (`POST /habits`) — Telegram
понимает только их ежедневную отметку и список, см. `specs/004-habits.md`.

Разбор сообщений сейчас основан на правилах/regex (`app/conversation/`), без LLM — см. `specs/003-conversation.md`.

### Настройка утреннего брифинга

1. Напишите боту `/start` — он ответит вашим Telegram ID.
2. Впишите его в `.env` как `owner_telegram_user_id`.
3. Проверьте (или настройте) `morning_briefing_hour`/`morning_briefing_minute` — время отправки по местному часовому поясу машины, на которой запущен бот.
4. Перезапустите бота — каждый день в указанное время придёт брифинг: главная задача дня, остальные задачи, просроченные, привычки со стриком, цели с прогрессом и проекты.

Без AI: текст собирается из Tasks + Habits + Goals + Memory шаблоном (`app/scheduler/briefing.py`), см. `flows/001-morning-briefing.md`. Цели — из Goals Service (`POST /goals`, прогресс через `PATCH /goals/{id}`), проекты — из Memory (тип `project`).

### Вечерняя рефлексия

Настраивается так же, как утренний брифинг: `evening_reflection_enabled`/`evening_reflection_hour`/`evening_reflection_minute` в `.env`. В указанное время бот присылает напоминание подвести итоги дня — ответ с «дневник:»/«рефлексия:»/«итоги дня:» сохраняется в Memory (тип `journal`). Без диалогового состояния — ответить можно в любой момент, не только сразу после напоминания, см. `flows/005-evening-reflection.md`.

### Напоминания о задачах

В отличие от брифинга (фиксированное время раз в день), напоминания привязаны к конкретной задаче: если у задачи есть точный срок («через 10 минут», «в 18:30»), раз в `task_reminders_interval_seconds` (по умолчанию 60) бот проверяет, не наступил ли срок, и присылает `⏰ Напоминание: «...»` один раз. «Завтра»/«в пятницу» и т.п. — это дни без точного времени (по умолчанию 09:00), напоминание для них сработает так же, в 09:00. Подробности и известные упрощения — `specs/002-tasks.md`.

### AI-фолбэк для непонятных сообщений (опционально)

Rule-based парсер понимает большинство сообщений сам, бесплатно и мгновенно. Если он не смог разобрать сообщение (не получилось выделить название задачи) и в `.env` заполнен `openrouter_api_key` — сообщение дополнительно уходит в LLM через [OpenRouter](https://openrouter.ai/) для повторной попытки. Без ключа всё работает как раньше, просто без этой подстраховки. Подробности — `specs/003-conversation.md`.

## API

При запуске API будет доступно по адресу: http://localhost:8000

### Основные эндпоинты:

- `GET /health` — Проверка состояния системы
- `GET /docs` — Swagger документация API
- `GET /redoc` — ReDoc документация API
- `GET /ui` — простейший веб-интерфейс (задачи/привычки/цели): статическая страница на vanilla JS, ходит в тот же REST API, что и бот. При первом открытии впишите свой Telegram ID — сохранится в localStorage браузера. Осознанное отступление от MVP.md (там веб explicitly не входит в MVP) — по просьбе пользователя, отдельной бизнес-логики не добавляет.

## Архитектурные принципы

1. **Исключительно Python** — весь бэкенд на Python
2. **FastAPI + PostgreSQL** — основной стек технологий
3. **Без прямого доступа AI к БД** — все через сервисный слой
4. **Каждая возможность — отдельный сервис** — модульная архитектура
5. **No Large Files** — файлы не более 250-300 строк
