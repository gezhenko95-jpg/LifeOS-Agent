# Настройка новой машины

Проект живёт в приватном репозитории и работает на нескольких
компьютерах. Код синхронизируется гитом, секреты — нет: их в гите нет и
не будет. Этот файл про то, как за пять минут довести свежий клон до
рабочего состояния.

> **На Google Drive проект класть не надо.** Диск синхронизирует `.git/`
> пофайлово и в произвольный момент — на двух машинах это рано или
> поздно даёт битый индекс и потерянные коммиты. Синхронизация тут
> git, а не Диск. Единственное, чему на Диске место, — папка
> `Файлы для дизайна стилей/` (исходники картинок, ~48 МБ, в гите их
> нет намеренно: в репозитории лежат только сжатые версии).

## Быстрый путь

```bash
git clone https://github.com/gezhenko95-jpg/LifeOS-Agent.git
cd LifeOS-Agent/lifeos-agent
pip install -e .[dev]
cd ..
bash lifeos-agent/scripts/pull_secrets.sh     # если есть доступ по ssh
python lifeos-agent/scripts/doctor.py
```

Последняя команда — главная. Она проверяет машину целиком и говорит,
чего не хватает и какой командой это чинится. Красный пункт — работать
не получится, жёлтый — часть фич просто выключена.

## Что нужно под какую задачу

Не всё нужно всем. Три уровня:

| Хочу | Что нужно |
|---|---|
| Писать код, гонять тесты | Только клон и зависимости. Ни секретов, ни ключей: тесты идут на SQLite, а у всех токенов в `Settings` пустые значения по умолчанию |
| Смотреть `/ui` локально | Плюс `.env` с заполненным `api_token` |
| Деплоить | Плюс SSH-ключ и алиас `lifeos-eu` |

## Секреты: откуда брать

**Источник правды — сервер.** В `/opt/lifeos/.env` лежит то, что реально
крутится на проде. Оттуда и забираем:

```bash
bash lifeos-agent/scripts/pull_secrets.sh
```

Скрипт кладёт `.env`, `token.json` и `credentials.json` на место, а
существующие файлы не затирает молча — делает копию с меткой времени.

Если ssh ещё нет, начните с образца и заполните руками:

```bash
cp lifeos-agent/.env.example lifeos-agent/.env
```

В `.env.example` перечислены **все** настройки с комментариями, что
каждая делает и что сломается, если оставить пустой. Пустое значение в
образце = сюда надо вписать своё; заполненное = рабочий дефолт, можно
не трогать.

**Пересылать секреты мессенджером, почтой или Диском не надо.** Либо
через ssh скриптом выше, либо флешкой, либо через менеджер паролей.

## Доступ к серверу

Нужен только для деплоя. **Не копируйте ключ с другой машины** — заведите
свой. Тогда у каждого компьютера отдельный ключ, и любой можно отозвать,
не трогая остальные.

На новой машине:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/lifeos_home -C "home-pc"
```

Публичную часть (`~/.ssh/lifeos_home.pub`) добавить на сервер — с машины,
доступ с которой уже есть:

```bash
ssh lifeos-eu "cat >> ~/.ssh/authorized_keys" < ~/.ssh/lifeos_home.pub
```

И дописать в `~/.ssh/config` на новой машине:

```
Host lifeos-eu
  HostName 148.135.208.126
  User root
  IdentityFile ~/.ssh/lifeos_home
```

Проверить: `ssh lifeos-eu true` должно отработать молча.

## Чего делать нельзя

**Не запускайте бота локально с боевым токеном.** Telegram пускает
только одного потребителя `getUpdates`: домашний бот начнёт драться с
серверным, и прод посыплется с `409 Conflict`. Нужен бот для проверок —
заведите отдельного в @BotFather и пропишите его токен в локальный
`.env`.

**Не коммитьте секреты.** `.gitignore` закрывает `.env`, `token.json`,
`credentials.json` — но проверять глазами перед коммитом всё равно
стоит. Пароль однажды уже лежал открытым текстом в `HANDOFF.md`, потому
что файл целиком вставляли в чаты.

**Не деплойте руками через ssh и tar.** Только
`bash lifeos-agent/scripts/deploy.sh` — он собирает архив из коммита, а
не из рабочей папки, и именно это не даёт трём копиям кода разъехаться.

## Ежедневные команды

```bash
cd lifeos-agent
python -m pytest -q                                    # тесты
python -m ruff check app tests migrations scripts
python -m black --check app tests migrations scripts
cd ..
bash lifeos-agent/scripts/deploy.sh                    # деплой
bash lifeos-agent/scripts/deploy.sh --check            # сверка прод/гит
python lifeos-agent/scripts/doctor.py                  # что не так с машиной
```

**pytest запускать только из `lifeos-agent/`.** Из корня ломаются
импорты и получается около 530 «падений» на пустом месте.

---

## Если что-то не работает

Сначала `python lifeos-agent/scripts/doctor.py` — он проверяет
инструменты, репозиторий, секреты, ssh и прод, и почти всегда сразу
показывает причину.

Дальше — `HANDOFF.md` в корне: там состояние проекта, что сделано, что
осталось и накопленные грабли.
