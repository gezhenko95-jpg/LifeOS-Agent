# Architecture Decisions

В этом документе фиксируются важные архитектурные решения проекта.

Каждое решение должно иметь причину.

---

## ADR-001

### Используется модульный монолит

Причина:

- проще разработка;
- проще тестирование;
- проще деплой;
- меньше сложность.

Микросервисы рассматриваются только после появления реальной необходимости.

---

## ADR-002

### LLM не имеет прямого доступа к БД

Причина:

- безопасность;
- контроль бизнес-логики;
- возможность заменить модель без изменения системы.

---

## ADR-003

### Spec First Development

Любая новая возможность проходит путь:

Идея
→ Спецификация
→ Обсуждение
→ Реализация
→ Тестирование

Без спецификации код не пишется.

---

## ADR-004

### Простые решения предпочтительнее сложных

Если задачу можно решить обычным кодом, не нужно использовать LLM.

LLM применяется только там, где действительно требуется понимание естественного языка, анализ или генерация текста.

---

## ADR-005

### Один сервис — одна ответственность

Каждый сервис отвечает только за свою предметную область.

Запрещено смешивать бизнес-логику нескольких сервисов в одном модуле.
