# Mood Tracker Specification

---

# Цель

Трекер настроения в стиле Daylio — один тап по эмодзи, без формы и без
обязательного текста. Явно запрошено владельцем (см. HANDOFF, раздел
«Что сделать в начале новой сессии», п.3): «встраивается в
evening_reflection.py + scheduler/charts.py».

---

# Бизнес-требования

- отметить настроение — один тап по одной из пяти эмодзи-кнопок
  (😢 1 · 😕 2 · 😐 3 · 🙂 4 · 😄 5), без обязательного текста;
- точка входа №1 — **под вечерним дневниковым вопросом** (21:00,
  `send_evening_reflection_job`): кнопки добавляются к уже существующему
  AI-вопросу, не отдельным сообщением — не плодим push-слоты
  (specs/016-engagement-hooks.md, тот же довод, что у «⭐ Сохранить» под
  дайджестом);
- точка входа №2 — раздел «📊 Настроение» в постоянном меню: то же самое
  действие в любой момент дня, не только вечером, плюс история;
- одно значение в день не форсируется — можно отметить настроение
  несколько раз, история хранит все точки (Daylio делает так же, повторная
  отметка — это уточнение, а не ошибка);
- график настроения за последние 30 дней — в еженедельном дайджесте,
  рядом с существующими графиками задач/привычек;
- удаление записи — кнопка, без подтверждения (как везде в проекте).

---

# Архитектура

Восьмой домен по тому же шаблону: `app/mood/{models,repository,service,
schemas}.py`. REST API и `/ui`-карточка — в этой же итерации (тот же
довод, что у personal CRM, specs/018 — не откладываем «полный арсенал»
на потом).

Домен-буква callback_data — `m` (свободна, см.
app/telegram/keyboards.py — список домен-букв). Действие `m|s|{score}`
переиспользуется в двух местах: под вечерним вопросом (сообщение
редактируется на месте, тот же приём, что у `d|f` — сохранить дайджест)
и в разделе «📊 Настроение» (сообщение обновляется списком).

# Модель данных (`app/mood/models.py`)

## MoodEntry

| Поле | Тип | Комментарий |
|---|---|---|
| `id` | int, PK | |
| `telegram_user_id` | BigInteger, indexed | владелец |
| `score` | int | 1–5, обязательно |
| `note` | String(500), nullable | не заполняется кнопкой, задел на будущее (текстовый ввод — не в этой итерации) |
| `logged_at` | DateTime(tz), indexed | `server_default=func.now()` |

Никакой отдельной таблицы тегов/причин настроения (в отличие от полного
Daylio) — см. «Что НЕ входит».

---

# Бот (`app/telegram/`)

- Под сообщением вечерней рефлексии (`send_evening_reflection_job`) —
  5 кнопок-эмодзи, `m|s|{score}`. Тап дописывает в конец сообщения
  строку `✅ Настроение: 🙂 (4/5)` и убирает клавиатуру (повторный тап
  на то же сообщение невозможен физически, тот же приём, что у
  digest-save). Награда — как за любое «сделал»-действие
  (specs/016-engagement-hooks.md).
- Пункт постоянного меню «📊 Настроение» (`MENU_MOOD`) → экран раздела:
  сразу 5 эмодзи-кнопок (`m|s|{score}`) + «📋 История» (`m|l`).
- `m|l` — последние записи (дата, счёт), кнопка удаления `m|x|{id}`.

---

# График (`app/scheduler/charts.py`, расширение)

Третий подграфик в `render_chart` (после столбиков задач и тепловой
карты привычек) — линия/точки настроения за последние 30 дней,
1–5 по оси Y. Строится, только если есть хоть одна запись за период
(тот же принцип, что у `has_habits`/`has_task_activity`) — иначе как и
сейчас, просто пропускается.

---

# API (`app/api/mood.py`)

- `POST /mood/entries` — записать (score, note опционален)
- `GET /mood/entries?telegram_user_id=&limit=` — последние записи
- `DELETE /mood/entries/{id}`

---

# `/ui`

Девятая вкладка «Настроение», карточка с 5 кнопками-эмодзи сверху
(тап — сразу запись, без формы, тот же принцип «один тап», что и в
боте) и списком последних записей снизу.

---

# Что НЕ входит

- теги/причины настроения (только числовая оценка);
- обязательный текстовый комментарий к записи;
- форсирование «одна запись в день» — история открытая, как в Daylio;
- напоминание «ты забыл отметить настроение сегодня» — отдельный
  push-слот, не в этой итерации (риск повторить ошибку из
  specs/016 — лишний слот без действия хуже, чем отсутствие метрики);
- редактирование записи — только удалить и отметить заново.

# План реализации

1. `app/mood/{models,repository,service,schemas}.py`, миграция
   `020_create_mood_entries`.
2. `app/core/container.py::build_mood_service`.
3. `app/scheduler/charts.py` — третий подграфик.
4. Бот: `keyboards.py` (кнопки под рефлексией + экран раздела + список),
   `jobs.py::send_evening_reflection_job` — `reply_markup`,
   `callbacks.py::_handle_mood_action`, `handlers.py` — пункт меню.
5. `app/api/mood.py`, регистрация в `app/main.py`.
6. `/ui`: вкладка, карточка, JS.
7. Тесты: repository/service/callbacks/charts/keyboards.

# Definition of Done

- Все пункты бизнес-требований реализованы, кроме раздела «Что НЕ
  входит».
- Тесты зелёные, ruff/black чисты.
- Миграция прогнана на проде, `/health` и `/ui/` отвечают.
- Проверено вручную: кнопки под вечерней рефлексией, раздел в меню,
  REST API, карточка на `/ui`, график в ближайшем еженедельном
  дайджесте.
