# Focus Sessions (Pomodoro) Specification

---

# Цель

Последнее из трёх, что владелец просил в бэклоге 23-24.08 (после
personal CRM и mood tracker) — таймер+лог в стиле Pomodoro. Решения
уточнены заранее (не додуманы):

1. Старт — кнопка «25 мин» по умолчанию + возможность задать свою
   длительность.
2. Полный цикл: бот сам считает и перерыв, шлёт уведомление по его
   окончании тоже (не только «работа закончена»).
3. Привязка к задаче — опциональная.
4. Статистика — карточка на `/ui` + строка в воскресном дайджесте.

Скоуп сознательно узкий (см. HANDOFF): не блокировщик приложений (бот
физически не может блокировать другие программы, в отличие от
Reclaim/Motion) — реалистичный масштаб для Telegram-бота таймер+лог.

---

# Архитектура — опрос БД, не `job_queue.run_once`

**API и бот — разные процессы** (`lifeos-api`/`lifeos-bot`, отдельные
контейнеры docker-compose). `context.job_queue.run_once()` живёт только
в памяти процесса бота: не виден из API (сессию нельзя было бы
отменить/увидеть, если бы её завёл `/ui`) и не переживает рестарт бота
(а деплой в этом проекте перезапускает контейнер бота на каждую
правку). Обе проблемы решены уже существующим в проекте паттерном —
`TaskRepository.list_due_unreminded`/`send_task_reminders_job` и
`HabitRepository`/`send_habit_reminders_job`: повторяющаяся джоба
опрашивает БД на «пора» по хранимому времени, а не держит таймер в
памяти.

`FocusSession` хранит `work_ends_at`/`break_ends_at` — конкретные
моменты, не длительности. Новая повторяющаяся джоба
`send_focus_notifications_job` (интервал как у джоб напоминаний, см.
`task_reminders_interval_seconds`) на каждый тик:
- находит сессии `in_progress` с `work_ends_at <= now` и ещё не
  уведомлённые → шлёт «работа окончена, начался перерыв N мин»,
  переводит в `on_break`, считает `break_ends_at`;
- находит сессии `on_break` с `break_ends_at <= now` и ещё не
  уведомлённые → шлёт «перерыв закончен, сессия завершена»,
  переводит в `completed`.

Без фильтра по `telegram_user_id` в самом опросе — проект single-user
(PROJECT.md), тот же приём, что у `list_due_unreminded`.

**Плата за простоту** (тот же принцип, что у `pending_input.py`):
уведомление опаздывает максимум на длину интервала опроса — не
мгновенно секунда в секунду, а с точностью до опроса. Для таймера в
десятки минут это не заметно.

# Модель данных (`app/focus/models.py`)

## FocusSession

| Поле | Тип | Комментарий |
|---|---|---|
| `id` | int, PK | |
| `telegram_user_id` | BigInteger, indexed | |
| `task_id` | int, FK `tasks.id` ON DELETE SET NULL, nullable | опциональная привязка |
| `work_minutes` | int | длительность работы |
| `break_minutes` | int | длительность перерыва |
| `started_at` | DateTime(tz) | момент старта |
| `work_ends_at` | DateTime(tz) | `started_at + work_minutes` — по этому полю опрашивает джоба |
| `break_ends_at` | DateTime(tz), nullable | считается при переходе в `on_break` |
| `status` | str | `in_progress` / `on_break` / `completed` / `cancelled` |
| `work_notified_at` | DateTime(tz), nullable | уведомление «работа окончена» уже отправлено |
| `break_notified_at` | DateTime(tz), nullable | уведомление «перерыв окончен» уже отправлено |
| `created_at` | DateTime(tz) | |

Один активный (`in_progress`/`on_break`) сеанс на пользователя —
`start_session` бросает `ValueError`, если такой уже есть (Pomodoro по
смыслу однопоточный, параллельные сессии не имеют смысла).

# Бот

Домен-буква `z` (свободна, следующая после `m`/`z` в списке — см.
`app/telegram/keyboards.py`). Пункт постоянного меню «⏱ Фокус» → экран
раздела: кнопка «▶ 25 мин» (дефолт) + «➕ Своя длительность» (pending
input, "40" → 40 мин работы / 5 мин перерыв по умолчанию) + «✕
Прервать», если сессия уже идёт. Привязка к задаче — не через бота
(как и `contact_id` у задачи, только `/ui`).

# REST API (`app/api/focus.py`)

- `POST /focus/sessions` — старт
- `GET /focus/sessions/active` — текущая сессия или `null`
- `POST /focus/sessions/{id}/cancel`
- `GET /focus/sessions/stats` — `completed_count`/`total_minutes` за
  период (по умолчанию — 7 дней, для `/ui` и дайджеста)

# `/ui` и дайджест

Карточка «Фокус»: если сессия активна — статус (работа/перерыв) и
время до конца, иначе форма старта (25 мин по умолчанию + своя
длительность) + опциональный выбор задачи (как у привязки контакта).
Статистика недели — та же, что уходит в дайджест.

`weekly_digest.py` — новая строка «🍅 N сессий, M мин фокуса» тем же
паттерном, что остальные секции (`_format_*_section`).

---

# Что НЕ входит

- блокировка приложений/сайтов (см. «Цель» выше);
- редактирование длительности уже идущей сессии;
- несколько параллельных сессий;
- график сессий во времени (специфика "Итоги недели" уже перегружена —
  число сессий текстом в карточке и дайджесте достаточно).
