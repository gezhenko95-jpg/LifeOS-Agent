# Media Inbox Specification (вариант B)

---

# Цель

Два связанных, но независимых канала:

1. **Watchlist** — структурированный список «посмотреть/прочитать» (фильмы,
   книги, сериалы) с статусом и AI-рекомендацией — живёт в БД, как
   Tasks/Habits/Goals, управляется из Telegram-меню.
2. **Media Inbox** — сырые файлы (эскизы, скриншоты), которые пользователь
   присылает боту, автоматически раскладываются по фиксированному набору
   папок на Google Drive через AI-классификацию изображения. Скриншоты,
   опознанные как фильм/книга, дополнительно создают запись в Watchlist (п.1).

Не плодим папку на каждый фильм — это Watchlist-строка, не файловая
структура (ADR-004: простое решение вместо усложнения).

---

# Что НЕ входит

- OCR/vision для произвольных документов (PDF, текстовые файлы) — только
  изображения.
- Совместное редактирование/шаринг Drive-папок с другими людьми — проект
  single-user (PROJECT.md).
- Умные рекомендации по содержанию (например, "похоже на фильмы, которые
  тебе нравились") — только простая AI-подсказка "выбери один из списка",
  без персонализации сверх этого.
- Синхронизация статуса из внешних источников (Letterboxd, Goodreads и т.п.).

---

# Реализация двумя фазами

**Фаза 1 (эта сессия, ничего внешнего не требует)** — Watchlist как
отдельная фича, добавление через обычный текст, список и статус через
Telegram-меню. Работает полностью автономно, даже если Фаза 2 никогда не
будет сделана.

**Фаза 2 (требует ручной настройки Google Cloud OAuth пользователем)** —
приём фото в боте, AI-классификация изображения, загрузка в Drive по
папкам, авто-создание Watchlist-записи из скриншота, экспорт снапшота в
`Watchlist.md` на Drive, раздел в `/ui`.

Спека описывает обе фазы целиком (архитектура согласована заранее), но
Definition of Done и тестирование — только по факту реализации каждой.

---

# Фаза 1 — Watchlist

## Пользовательские сценарии

- «Хочу посмотреть Дюну» / «посмотреть фильм Дюна» → создаётся запись
  `media_type=movie, status=to_watch, title="Дюна"`.
- «Прочитать книгу Автостопом по галактике» → `media_type=book`.
- Просто «посмотреть Дюну» без слова «фильм»/«книга» → `media_type=other`
  (не гадаем на пустом месте — ADR-004).
- Кнопка «🎬 Посмотреть» в меню → список активных (`to_watch`) записей,
  под каждой — ✅ (отметить готовым) / 🗑 (удалить), как у привычек/задач.
- В списке — кнопка «🎲 Порекомендуй» (одна на всё сообщение, не под
  каждой строкой) → AI выбирает одну случайную/подходящую запись и
  коротко объясняет выбор (если AI недоступен — просто случайный выбор
  без объяснения, без ошибки).

## Модель данных

Новая таблица `watchlist_items` (миграция `010_add_watchlist_items.py`):

- `id` — PK
- `telegram_user_id` — BigInteger, индекс
- `title` — String(255)
- `media_type` — String(20): `movie` | `book` | `other`
- `status` — String(20): `to_watch` | `done`, default `to_watch`
- `source` — String(20): `manual` | `photo` (Фаза 2), default `manual`
- `drive_file_url` — String(500), nullable (заполняется в Фазе 2)
- `created_at` — DateTime(timezone=True), server_default=now()
- `completed_at` — DateTime(timezone=True), nullable

## Слои (по образцу app/goals/*)

`app/watchlist/models.py`, `repository.py` (add/get_by_id/list_by_user/
save/delete), `service.py` (create_item, list_active_items, mark_done,
delete_item, pick_recommendation).

## Conversation Engine

`app/conversation/intent.py` — новый `Intent.ADD_WATCHLIST_ITEM`.

`app/conversation/parser.py` — триггерные фразы в начале сообщения:
`"посмотреть фильм"`, `"посмотреть сериал"` → movie; `"прочитать книгу"` →
book; `"хочу посмотреть"`, `"хочу прочитать"`, `"посмотреть"` (без слов
фильм/сериал/книга следом) → other. Порядок проверки — от специфичных
фраз к общим (как `_QUERY_BY_DATE_KEYWORDS` перед общим ADD_TASK), иначе
"посмотреть фильм X" ошибочно распознается как other. Название — остаток
строки после вырезанной фразы (`_remove_keyword`-подобно).

`app/conversation/engine.py` — `_add_watchlist_item`, по образцу
`_add_task`, ответ `"Добавил в список: «{title}» 🎬"` (🎬/📖/🎯 — в
зависимости от media_type).

Статус (✅/🗑) — только через inline-кнопки, НЕ через свободный текст
("посмотрел X"), чтобы не пересекаться с уже занятыми `COMPLETE_TASK`-
триггерами ("выполнил", "сделал", "готово").

## Telegram

`app/telegram/keyboards.py` — `MENU_WATCHLIST = "🎬 Посмотреть"`,
`build_watchlist_message(items) -> tuple[str, InlineKeyboardMarkup]` (по
образцу `build_habits_message`), callback-префикс `w|d|{id}` (done),
`w|x|{id}` (delete), плюс одна кнопка `w|r|0` "🎲 Порекомендуй" в конце
клавиатуры (не в каждой строке).

`app/telegram/callbacks.py` — обработка `w|*`, тот же паттерн, что `h|*`.

`app/telegram/handlers.py` — `MENU_WATCHLIST` в `_MENU_ACTIONS`.

## AI-рекомендация

`WatchlistService.pick_recommendation(telegram_user_id, ai_client=None)`:
без AI — просто `random.choice` по активным записям, короткий текст
"Как насчёт «{title}»?". С AI — один короткий (≤20 слов) комментарий,
почему именно этот вариант (промпт получает весь список + выбранное
случайным образом название — AI не выбирает сам, только комментирует,
чтобы результат был воспроизводим и не зависел от галлюцинаций AI по
списку). Ошибка AI — тихий фолбэк на вариант без AI (тот же принцип, что
везде в проекте).

## Definition of Done (Фаза 1)

- `parser.py`: все триггерные фразы, порядок специфичное/общее, пустой
  заголовок после вырезания фразы;
- `WatchlistService`: create/list/mark_done/delete/pick_recommendation
  (пустой список, с AI, без AI, ошибка AI);
- `build_watchlist_message`: пусто/несколько записей/эмодзи по типу;
- `callbacks.py`: done/delete/recommend, не найдено;
- живая проверка в контейнере: добавить через текст, увидеть в меню,
  отметить готовым, удалить, убрать тестовые записи после проверки.

# Фаза 2 — Media Inbox (Google Drive)

## Что нужно от пользователя заранее (сделать самостоятельно)

1. Google Cloud Console → новый проект → включить **Google Drive API**.
2. OAuth consent screen — тип **External**, статус **Testing** (личный
   проект, не нужна публикация), добавить свой аккаунт в тестовые
   пользователи.
3. Credentials → **OAuth client ID** → тип **Desktop app** → скачать
   `credentials.json`.
4. Один раз локально (не в контейнере) прогнать authorization code flow
   в браузере — бот один раз попросит открыть ссылку и вставить код,
   дальше работает по refresh-токену без участия пользователя.
5. Скинуть `credentials.json` (и получившийся `token.json`) в
   `lifeos-agent/` — уже в `.gitignore`, не попадёт в репозиторий.

Это отдельный шаг вне чата — сервис-аккаунт не подходит (личный Google
Диск, не Workspace), нужен именно OAuth от имени пользователя.

## Приём фото

`app/telegram/handlers.py` — новый `MessageHandler(filters.PHOTO, ...)`
→ скачивает файл через `context.bot.get_file`, передаёт байты дальше.

## AI-классификация изображения

`app/ai/client.py` — расширить `AIClient.complete` (или новый метод
`classify_image`) поддержкой vision-запроса (OpenRouter, модель с
поддержкой картинок, например `openai/gpt-4o-mini`). Промпт: вернуть
JSON `{category: "sketch"|"movie"|"book"|"other", title: str|null}` —
`title` заполняется только если на скрине читается название фильма/книги.
Не угадывать, если не уверена — `category: "other"`.

## Раскладка по Drive

`app/drive/client.py` — тонкая обёртка над `google-api-python-client`:
`ensure_folder(name) -> folder_id` (создаёт при отсутствии, кэширует id),
`upload_file(folder_id, filename, content) -> url`.

Фиксированные папки: `Эскизы`, `Кино и книги`, `Разное` (3, не больше —
см. "Что НЕ входит").

## Связка с Watchlist

Если `category` — `movie`/`book` и `title` не пустой — помимо загрузки
файла в Drive, создаётся `WatchlistItem(source="photo",
drive_file_url=...)` через уже существующий `WatchlistService.create_item`
(Фаза 1) — не дублируем логику.

## Экспорт снапшота

`app/scheduler/watchlist_export.py::export_watchlist_to_drive` — раз в
неделю (или по кнопке) перегенерирует `Watchlist.md` в корне Drive
целиком из текущих `to_watch`-записей (не аппендит построчно — проще и
не может рассинхронизироваться при удалении/отметке готово).

## `/ui`

Раздел на существующей `app/web/static/index.html` (или новый
`/ui/watchlist`) — читает уже существующий REST `app/watchlist/api.py`
(GET-список), рендерит таблицу. Без записи с фронта — только просмотр,
изменения только через бота (не плодим два способа мутировать одни и те
же данные).

## Definition of Done (Фаза 2)

- `classify_image` — мок AI-ответа, невалидный JSON не роняет функцию;
- `DriveClient` — мок `google-api-python-client`, `ensure_folder`
  кэширует, не создаёт дубликат папки при повторном вызове;
- ручная проверка с реальным Drive (после того как пользователь пройдёт
  OAuth) — прислать эскиз → появился в папке "Эскизы"; прислать скрин
  фильма → появился и в "Кино и книги" на Drive, и в Watchlist в боте.
