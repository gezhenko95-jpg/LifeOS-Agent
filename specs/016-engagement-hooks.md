# Engagement Hooks Specification

---

# Цель

Владелец пользуется ботом каждый день только ради дайджестов каналов.
Остальные push-сообщения (утренний брифинг, утренняя/вечерняя рефлексия,
дневной и вечерний чек-ин) он «иногда читает, но не действует» —
собственные слова из чата 23.08. Причина не в количестве push (дайджест
тоже push), а в том, что почти все они требуют **напечатать текстовый
ответ**, а совершённое действие никак не вознаграждается. Задача спеки —
убрать эту причину точечно, не изобретая новый домен.

---

# Диагноз (не переоткрывается, если новых данных не появится)

| Слот | Что просит | Кнопка? | Награда за действие? |
|---|---|---|---|
| 10:00 утренний брифинг | ничего (только чтение) | — | — |
| 10:30 утренняя рефлексия | напечатать ответ | нет | нет |
| 14:00 дневной чек-ин | привычки — тап; «как дела» — печатать | частично | нет |
| 19:00 вечерний итог (+50% gap-вопрос) | иногда печатать | нет | нет |
| 21:00 вечерняя рефлексия | напечатать ответ | нет | нет |
| вс. дайджест недели | ничего | — | — |
| дайджест каналов | ничего | — | — (но именно это работает) |

Вывод: то, что не просит ничего и не наказывает бездействием — работает.
Значит первый шаг — не «добавить ещё функциональность», а **вознаградить
то действие, которое пользователь и так иногда совершает**, и снять
часть «домашних заданий» там, где это дёшево.

---

# Бизнес-требования этой итерации

1. Любое «сделал» действие в чате или по кнопке (создал задачу, выполнил
   задачу, отметил привычку, продвинул/завершил цель, отметил
   просмотренное/прочитанное на полке, записал дневник, ответил на
   проактивный вопрос) засчитывает **сегодняшний визит** в существующей
   мини-игре rewards (`app/rewards/`) — без отдельного похода в `/ui` и
   клика «Забрать».
2. Награда видна сразу в том же сообщении, где произошло действие —
   «🪙 +N · 🔥 стрик» одной строкой снизу.
3. Награда начисляется **один раз в день**, как и раньше (не за каждое
   действие) — это не новая экономика, а просто новый способ получить
   уже существующую награду, без лишнего клика.
4. Утренняя рефлексия (10:30) сливается в утренний брифинг (10:00) —
   тем же паттерном, что уже использует вечерний чек-ин (19:00,
   `_EVENING_GAP_CHANCE`): вопрос дописывается снизу к брифингу вместо
   отдельного сообщения. Минус один push в день.

# Что сознательно НЕ входит в эту итерацию

- Кнопки вместо свободного текста для рефлексии/gap-вопросов — вопросы
  генерируются AI и открытые по смыслу (это дневник, не тест с
  вариантами), сузить их до кнопок значит менять продукт вопроса, а не
  снимать трение. Требует отдельного решения о том, какие вопросы вообще
  можно закрыть до конечного набора ответов — не в этой итерации.
- Новая механика измерения (открыл/не открыл/нажал) — отдельная спека,
  если этой итерации окажется недостаточно.
- ⭐ «Сохранить» под постом дайджеста и «год назад ты писал» — отдельный
  пункт (см. ниже, раздел «Дайджест»), реализуется в этой же сессии, но
  логически не связан с наградами.

# Модель данных

`app/rewards/service.py::RewardsStatus` — новое поле:

```python
just_claimed: bool = False
```

`True`, только если ИМЕННО этот вызов `claim_today` перевёл день из
«не забрано» в «забрано» (т.е. `has_checkin_on` до вызова было `False`).
Повторные вызовы в тот же день — `claimed_today=True`,
`just_claimed=False`, текст награды не показывается повторно. Ничего в
БД не меняется — поле есть только в статусе, который и так пересобирается
на каждый вызов.

# Точки начисления

## Через кнопки (`app/telegram/callbacks.py`)

Общий хелпер:

```python
async def _reward_line(session: AsyncSession, telegram_user_id: int) -> str:
    status = await build_rewards_service(session).claim_today(telegram_user_id)
    if not status.just_claimed:
        return ""
    return f"\n\n🪙 +{status.coins_today} · 🔥 {status.streak}"
```

Подключается к результату этих (и только этих) действий — «сделал»,
а не «посмотрел» или «удалил»:

| Домен | action | Что засчитывается |
|---|---|---|
| `t` (task) | `c` | задача отмечена выполненной |
| `h` (habit) | `d` | привычка отмечена сегодня |
| `g` (goal) | `u` | прогресс цели увеличен (не `p` — уменьшение прогресса не награда) |
| `g` (goal) | `c` | цель завершена |
| `w` (watchlist) | `d` | пункт отмечен просмотренным/прочитанным |

Строка добавляется только если сервисный метод вернул реальную сущность
(не `None`) — «отметил несуществующую/чужую задачу» не награждается.

## Через свободный текст (`app/conversation/engine.py`)

`ConversationEngine` получает новый опциональный параметр
`rewards_service: RewardsService | None = None` (тот же паттерн
опциональности, что у `pending_prompt_service`/`watchlist_service` —
никого не ломает, кто не передаёт). Награда дописывается к:

- успешному созданию задачи (`EngineResult.created_task is not None`);
- успешной записи в дневник (`_try_capture_journal`, возврат
  `"📝 Записал в дневник."`);
- успешно распознанному ответу на проактивный вопрос
  (`_try_answer_pending_prompt`, `handled_reply is not None`).

`COMPLETE_TASK`/`HABIT_DONE`/`ADD_WATCHLIST_ITEM` через чат НЕ
награждаются в этой итерации — у них сейчас нет структурного признака
успеха (просто строка текста, включая случай "не нашёл"), а гадать по
тексту — тот самый хрупкий паттерн, которого AUDIT.md (A-4) уже избавился
для задач. Кнопочный путь (`callbacks.py` выше) для этих трёх действий
уже покрывает награду; дублировать через текстовый ввод — не обязательно
для MVP.

`build_engine` в `app/core/container.py` собирает `RewardsService` и
передаёт его, как остальные сервисы.

# Слияние утренней рефлексии в брифинг

`send_morning_reflection_job` (10:30) удаляется как отдельная джоба.
`send_morning_briefing_job` (10:00) после сборки текста брифинга
опционально дописывает вопрос снизу — тем же вызовом
`PendingPromptService.pick_morning_reflection`, что раньше вызывался
из отдельной джобы, и тем же паттерном, что уже применяет
`send_evening_checkin_job` для gap-вопроса (`text = f"{text}\n\n{question}"`).
Регистрация в `app/telegram/bot.py`: убрать `run_daily` для 10:30,
джобу `send_morning_reflection_job` удалить из `jobs.py` вместе с тестами
(логика переехала внутрь `send_morning_briefing_job`).

# Дайджест: ⭐ Сохранить

**Пересмотрено при реализации.** Изначальный план («кнопка под каждым
постом») предполагал, что дайджест — это несколько отдельных постов с
собственными id. На деле `DigestService.build_digest_text` уже на этапе
сборки сплющивает посты в ОДИН текст (либо AI-саммари, либо
`_format_raw_posts` — конкатенация без сохранения границ/id постов), и
уходит одним сообщением. Кнопка на конкретный пост потребовала бы менять
формат хранения/сборки дайджеста ради одной кнопки — несоразмерно этой
итерации.

Вместо этого — одна кнопка `⭐ Сохранить дайджест` под всем сообщением
целиком (`callback_data="d|s|<digest_id>"`). Тап создаёт `MemoryEntry`
(`MemoryType.JOURNAL`, `source="digest_save"`) с полным текстом уже
отправленного дайджеста. Идемпотентность — по `(telegram_user_id,
digest_id, "date отправки")`: повторный тап на тот же дайджест в тот же
день не создаёт вторую запись (простая проверка перед вставкой, не новый
уникальный индекс — записей в день на один дайджест физически не может
быть больше одной, см. `send_digests_job`). Тот же `_reward_line` —
сохранение тоже «сделал», засчитывает сегодняшний визит.

Полноценная версия «кнопка под каждым постом» — не отменяется, а
переносится в отдельную будущую итерацию вместе с рефакторингом хранения
постов дайджеста (не в этой спеке).

# Важное расхождение, обнаруженное при реализации

При написании спеки казалось, что утренний брифинг и утренняя рефлексия
идут почти подряд («слить в один слот»). На деле дефолты разные:
`morning_briefing_hour=8` (не 10, как ошибочно указано в диагнозе выше),
`proactive_prompt_morning_hour=10`, `_minute=30`. То есть слияние двигает
момент вопроса с 10:30 на 8:00 (если на проде не переопределены в
`.env` — не проверялось, `.env` не в гите). Решено оставить слияние как
есть: раз джобы физически объединены в одну функцию, держать вопрос на
старом времени означало бы либо две отдельных отправки (не решает задачу
«меньше сообщений»), либо усложнение одной джобы условной логикой ради
несуществующей больше настройки. Время легко вернуть — поменять
`morning_briefing_hour`/`_minute` в `.env`, если 8:00 окажется неудачным
моментом для рефлексивного вопроса.

# Definition of Done

- `RewardsStatus.just_claimed` покрыт тестом: первый `claim_today` за
  день → `True`; второй подряд → `False`; после гонки (см. предыдущую
  сессию) — тоже `False` на проигравшем запросе.
- Кнопочные действия (`t|c`, `h|d`, `g|u`, `g|c`, `w|d`) — тест на
  «текст ответа содержит строку награды при первом действии за день» и
  «не содержит при втором».
- `ConversationEngine` с `rewards_service=None` (как раньше) работает
  без изменений — тест на обратную совместимость.
- Утренняя рефлексия видна в тексте брифинга, отдельной джобы для неё
  в `app/telegram/bot.py` больше нет; существующие тесты брифинга и
  рефлексии обновлены, не задублированы.
- Дайджест: `⭐ Сохранить` создаёт запись в памяти и не создаёт вторую
  при повторном тапе на тот же пост (идемпотентность по id поста).
- Все существующие тесты (867 на момент написания) зелёные, ruff/black
  чисты.
