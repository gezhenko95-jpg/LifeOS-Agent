# Habits Service Specification

---

# Цель

Habits Service отвечает за хранение привычек пользователя и учёт их
ежедневного выполнения. Это единственный сервис, который имеет право
читать и изменять таблицы `habits` и `habit_logs`.

---

# Бизнес-требования

- пользователь заводит привычку обычным сообщением в Telegram;
- пользователь может посмотреть список активных привычек с текущим
  стриком (сколько дней подряд выполнялась, включая сегодня);
- пользователь может отметить привычку выполненной сегодня по названию
  (без id), как и с задачами;
- повторная отметка в тот же день не создаёт дубликат и не ломает стрик;
- пользователь может удалить привычку.

В отличие от Memory/Goals, привычки требуют ежедневного касания через
Telegram — поэтому, в порядке исключения, для них заведены отдельные
rule-based интенты в Conversation Engine (см. `specs/003-conversation.md`).

# Модель данных

`app/habits/models.py`:

## Habit

| Поле | Тип | Описание |
|---|---|---|
| id | int | первичный ключ |
| telegram_user_id | bigint | владелец привычки |
| title | str(255) | название |
| archived | bool, default False | архивная привычка не в списках |
| created_at | datetime | дата создания |

## HabitLog

| Поле | Тип | Описание |
|---|---|---|
| id | int | первичный ключ |
| habit_id | int, FK → habits.id | какая привычка |
| completed_on | date | за какой день отметка |
| created_at | datetime | когда фактически отмечено |

Уникальный индекс `(habit_id, completed_on)` — защита от дублей за один день.

# API

Слой `app/api/habits.py` — только вызовы сервиса.

- `POST /habits` — создать привычку
- `GET /habits?telegram_user_id=...` — список активных со стриком
- `POST /habits/{id}/complete` — отметить выполненной сегодня (идемпотентно)
- `DELETE /habits/{id}` — удалить

---

# Сервис (`app/habits/service.py`)

- `create_habit(telegram_user_id, title) -> Habit`
- `list_active_habits(telegram_user_id) -> list[Habit]`
- `mark_done_today(telegram_user_id, title_query) -> Habit | None` — нечёткий
  поиск подстроки среди активных привычек (как у Tasks); если уже отмечено
  сегодня — не создаёт второй лог, просто возвращает привычку
- `get_streak(habit_id) -> int` — количество подряд идущих дней с логом
  считая от сегодня назад; простой Python-цикл по датам (без window-функций
  БД — ADR-004: не усложнять там, где хватает обычного кода)
- `delete_habit(habit_id) -> Habit | None`

---

# Репозиторий (`app/habits/repository.py`)

Только работа с БД: CRUD для `Habit` + `add_log`, `has_log_on`,
`list_logs(habit_id)` (для расчёта стрика сервисом).

---

# Разбор в Telegram (гибрид с Conversation Engine)

- `"привычки"` / `"мои привычки"` → `Intent.LIST_HABITS`
- `"привычка <название>"` → `Intent.HABIT_DONE`, остаток текста — подстрока
  для поиска

Проверяются раньше `COMPLETE_TASK`/`DELETE_TASK`, чтобы «привычка почитал»
не пытался найти задачу с таким названием.

---

# Definition of Done

- привычка создаётся и сохраняется;
- повторная отметка в один день не дублирует лог;
- стрик считается корректно (проверено тестами на разрывы дней);
- покрыт unit-тестами (service с замоканным repository) и интеграционным
  тестом API;
- 2 новых интента протестированы в parser.py/engine.py.
