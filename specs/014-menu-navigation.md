# 014 — Навигация по разделам (меню второго уровня)

## Цель

Кнопка постоянного меню умела ровно одно действие: «🎬 Посмотреть» =
показать полку, «📝 Дневник» = открыть запись. Всё остальное в разделе
(добавить на полку, перечитать старые записи, найти запись по теме,
завести дайджест, добавить в него канал) существовало только в виде
команд и фраз — про которые надо помнить, что они есть, и печатать их
без опечаток.

**Одно правило на все разделы.** Кнопка меню, за которой стоит домен
(задачи, привычки, цели, дневник, полка, дайджесты), всегда открывает
**экран раздела**: заголовок, строка-подсказка и ряд действий
«открыть список» + «добавить». Само действие делают inline-кнопки.
Никаких исключений: раньше «📋 Задачи» открывали список сразу, «➕
Задача» была отдельной кнопкой меню, «🎬 Посмотреть» — тоже сразу
список, и что произойдёт по нажатию, приходилось помнить для каждой
кнопки отдельно.

Кнопки-утилиты без своего домена и списка («📊 Инсайты», «🌐 Сайт»,
«❓ Помощь», «📰 Дайджест» — у последней сам список тем и есть экран)
остаются прямым действием: экран из одного пункта был бы лишним
щелчком.

## Что НЕ входит

- Не меняются механика и текст самих списков задач/привычек/целей — они
  и так открывались одним действием, экран раздела им не нужен.
- Никаких новых таблиц и миграций: экраны показывают то, что уже есть.
- Дерево остаётся двухуровневым (меню → экран раздела → действие). Более
  глубокая вложенность не вводится: в Telegram «назад» есть только тот,
  что нарисуем сами, и на третьем уровне пользователь перестаёт понимать,
  где он.
- Ожидание ввода после кнопки не переживает рестарт бота (см. ниже).

## Пользовательские сценарии

1. «📋 Задачи» / «🔁 Привычки» / «🎯 Цели» / «🎬 Посмотреть» → экран
   раздела: **Список** (тот же список с ✅/🗑, что и раньше) и
   **➕ Добавить**. После «➕ Добавить» бот просит текст, и следующее
   сообщение становится новой сущностью. У задачи текст по-прежнему
   проходит через движок (в нём может быть срок: «завтра в 19:00
   позвонить маме»), у привычки/цели/полки берётся целиком — кнопка уже
   сказала, что это, и слово-маркер («привычка», «фильм») не нужно.
2. «📝 Дневник» → **📖 Записи** (последние 8, дата + начало текста;
   кнопка с номером открывает запись целиком), **✍️ Новая запись**,
   **🔍 По теме** (следующее сообщение — поисковый запрос по дневнику).
3. «📰 Дайджест» → список тем кнопками + **➕ Новый дайджест**. Тема →
   её экран: какие каналы внутри, **📬 Что нового** (саммари прямо
   сейчас), **➕ Канал**, 🗑 под каждым каналом, **◀️ Назад**.
4. Из любого списка **◀️ Назад** возвращает на экран своего раздела.

Ответить на приглашение бота («что добавить?», «какой канал?») можно и
голосом — распознанный текст идёт тем же путём, что печатный.

## Слои

- `app/telegram/keyboards.py` — построители экранов (чистые функции):
  общий каркас `_section_screen` + `_open_and_add` (из них собраны все
  шесть разделов, поэтому расхождение стилей физически некуда внести),
  `build_tasks_menu`, `build_habits_menu`, `build_goals_menu`,
  `build_watchlist_menu`, `build_journal_menu`,
  `build_journal_entries_message`, `build_journal_entry_message`,
  `build_digest_menu_message`, `build_digest_detail_message`,
  `schedule_label` (одна формулировка расписания на команды и на экраны).
- `app/telegram/callbacks.py` — обработка нажатий, домены `j` (дневник) и
  `d` (дайджесты) плюс новые действия домена `w` (полка).
- `app/telegram/pending_input.py` — «следующее сообщение это ответ на
  кнопку»: вид ожидания и (для канала) id дайджеста.
- `app/telegram/handlers.py` — экраны разделов по кнопке меню и разбор
  ответа на ожидание (`_consume_pending_input`).
- `app/memory/service.py::get_entry`, `app/digest/service.py::get_digest`
  / `remove_channel_by_id` — доступ по id с проверкой владельца
  (`owned_or_none`), потому что в кнопке ездит id, а не имя.

## Решения

**Один код действия — один смысл во всех доменах.** `{домен}|m` — экран
раздела, `{домен}|l` — список, `{домен}|n` — добавить. Из-за этого
«-10%» у целей переехал с `g|n` на `g|p`: `n` теперь везде означает
«добавить», и оставить исключение значило бы вернуть ровно ту
разнобойность, ради которой всё и переделывалось.

**Почему id, а не имя, в `callback_data`.** Telegram даёт 64 БАЙТА на всю
строку. Имя дайджеста — до 50 символов и может быть кириллическим (в
UTF-8 это до 100 байт), то есть «d|s|Экология» рискует не поместиться.
Поэтому везде ездит числовой id, а имя достаётся из БД.

**Почему ожидание ввода живёт в `context.user_data`, а не в таблице
`pending_prompts`.** Таблица — про диалог бота с пользователем:
проактивный вопрос живёт часами, переживает рестарт, его ответ
разбирается через AI. Здесь другое — техническое «жду одно слово прямо
сейчас», актуальное секунды. Ради него не нужны ни миграция, ни поход в
БД на каждое сообщение (ADR-004). Плата: рестарт бота забывает ожидание,
и сообщение разберётся как обычный текст — пользователь нажмёт кнопку
ещё раз. Дневниковая запись («✍️ Новая запись») по-прежнему идёт через
таблицу: она осмысленна и через час.

**Ожидание одноразовое и снимается при уходе в другой раздел.** `pop`
снимает его сразу, ещё до обработки — даже неудачная попытка («канал не
найден») не оставляет ловушку, которая проглотит следующее сообщение.
Нажатие любой кнопки постоянного меню тоже снимает ожидание.

**Саммари дайджеста экранируется.** Текст приходит от модели и из постов
канала; угловые скобки в нём сломали бы `parse_mode=HTML` всего
сообщения — та же причина, по которой все пользовательские строки в
`keyboards.py` идут через `_esc`.

## Definition of Done

- [x] Все шесть доменных кнопок меню открывают экран раздела одного и
      того же вида; «◀️ Назад» с каждого вложенного экрана.
- [x] «📰 Дайджест» в постоянном меню; «➕ Задача» убрана — её работу
      делает «📋 Задачи» → «➕ Добавить».
- [x] Добавление на полку, создание дайджеста, добавление/удаление
      канала, поиск по дневнику — без единой напечатанной команды.
- [x] Ответ на приглашение работает и голосом.
- [x] Команды `/digest_*` продолжают работать как раньше.
- [x] Тесты: построители экранов, нажатия кнопок, ожидание ввода
      (`tests/telegram/test_menu_navigation.py`).
