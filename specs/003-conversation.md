# Conversation / Intent Parsing Specification

---

# Цель

Понимать, что хочет пользователь, из обычного сообщения в Telegram, и вызывать нужный сервис.

На этом этапе разбор намерения делается **без LLM** — простыми правилами и regex
(ADR-004: если задачу можно решить обычным кодом — не нужен LLM).

Интерфейс спроектирован так, чтобы позже `parse_intent` можно было заменить на
вызов AI Service (LLM), не меняя Telegram-слой и Tasks Service.

---

# Что НЕ входит

- Conversation Engine не хранит память, не пишет в БД напрямую и не решает,
  что ответить пользователю по существу — он только определяет намерение
  и делегирует его Tasks Service.

# Интенты

| Intent | Когда срабатывает | Пример |
|---|---|---|
| `ADD_TASK` | не подошло ни одно из ключевых слов ниже — весь текст (минус дата, минус «важно»/«срочно») считается названием задачи | «Завтра купить молоко» |
| `LIST_TASKS` | фраза начинается/содержит «покажи», «список задач», «мои задачи», «/tasks» | «Покажи задачи» |
| `QUERY_TASKS_BY_DATE` | содержит «что на», «что у меня на», «что было на», «что запланировано», «какие задачи», «какие дела», «что я собирался», «что я планировал» **и** в тексте нашлась дата (`date_parser`) | «Что я собирался сделать завтра?» |
| `RECALL` | содержит «напомни», «вспомни», «что я говорил (про/о)», «что ты знаешь (про/о)» | «Напомни, что я говорил про отпуск» |
| `LIST_HABITS` | содержит «привычки» | «Привычки» |
| `HABIT_DONE` | содержит «привычка » (со пробелом — отличает команду от разговорного упоминания слова) | «Привычка чтение» |
| `COMPLETE_TASK` | содержит «выполнил», «сделал», «готово», «закрой» | «Выполнил купить молоко» |
| `DELETE_TASK` | содержит «удали», «убери», «отмени» | «Удали молоко» |
| `JOURNAL_ENTRY` | начинается с «дневник», «рефлексия» или «итоги дня» | «Дневник: продуктивный день» |
| `HELP` | «/help», «помощь», «что ты умеешь» | «/help» |

Порядок проверки: HELP → LIST_TASKS → QUERY_TASKS_BY_DATE → RECALL →
LIST_HABITS → HABIT_DONE → COMPLETE_TASK → DELETE_TASK → JOURNAL_ENTRY →
иначе ADD_TASK. Привычки проверяются раньше COMPLETE_TASK, чтобы
«привычка сделал зарядку» не матчилось как задача (см.
`specs/004-habits.md`).

`QUERY_TASKS_BY_DATE` — если одна из ключевых фраз есть, но дату в тексте
`date_parser.extract_due_date` не нашёл (например «какие задачи вообще?»),
намерение тихо понижается до `LIST_TASKS` — вопрос без даты это просто
список. `ConversationEngine._list_tasks_by_date` берёт все активные задачи
через уже существующий `TaskService.list_active_tasks` и фильтрует по
`task.due_date.date() == due_date.date()` — Tasks Service не меняется.

`RECALL` — `ConversationEngine._recall` вызывает уже существующий
`MemoryService.search(telegram_user_id, query)` (случайно не был
подключён к чату) и возвращает до 5 совпадений. Query собирается вырезкой
ВСЕХ найденных триггерных фраз (не только первой — «напомни, что я
говорил про X» содержит две) плюс висящего предлога «про/о/об».

`ADD_TASK` дополнительно распознаёт приоритет: «важно»/«срочно» в
сообщении → `priority="high"` (см. `specs/002-tasks.md`).

# Извлечение даты (`app/conversation/date_parser.py`)

Понимает в тексте (регистронезависимо):

- «сегодня», «завтра», «послезавтра»;
- дни недели: «в понедельник» … «в воскресенье» (ближайший будущий);
- числовые даты: `dd.mm`, `dd.mm.yyyy`.

Возвращает `(due_date | None, остаток_текста)` — найденная дата-фраза
вырезается из текста, чтобы не попадать в название задачи.

Если дата не найдена — `due_date = None`, текст не меняется.

`date_parser.py::extract_recurrence` — отдельно распознаёт признак
повторения задачи («каждый день», «каждую неделю», «каждый месяц»,
«каждый/каждую <день недели>»); вызывается в `parser.py` ПЕРЕД
`extract_due_date` (см. `specs/002-tasks.md`, раздел Recurring Tasks).

# Результат разбора

```python
@dataclass
class ParsedIntent:
    intent: Intent
    title: str | None       # для ADD_TASK / COMPLETE_TASK / DELETE_TASK / HABIT_DONE / JOURNAL_ENTRY / RECALL
    due_date: datetime | None  # только для ADD_TASK / QUERY_TASKS_BY_DATE
    priority: str = "normal"   # только для ADD_TASK: "normal" | "high"
    recurrence: str | None = None  # только для ADD_TASK: "daily"|"weekly"|"monthly"
```

# Дневник (JOURNAL_ENTRY)

Триггерные слова: «дневник», «рефлексия», «итоги дня» — в начале сообщения
(регистронезависимо). Всё, что после триггерного слова и необязательного
`:` — текст записи. См. `flows/005-evening-reflection.md`.

`ConversationEngine` для этого intent вызывает
`MemoryService.save(type=MemoryType.JOURNAL, content=..., source="telegram")`
и отвечает «Записал в дневник» (или просит переформулировать, если текст
после триггера пуст).

# Conversation Engine (`app/conversation/engine.py`)

`handle_message(telegram_user_id: int, text: str) -> str`

1. `parse_intent(text)`.
2. В зависимости от intent — вызвать соответствующий метод `TaskService`.
3. Сформировать короткий текстовый ответ пользователю.
4. Если задача для COMPLETE/DELETE не найдена — вернуть понятное сообщение об ошибке, не бросать исключение наружу.

# AI fallback (гибрид)

Rule-based парсер остаётся основным путём (ADR-004: если задачу можно решить
обычным кодом — не нужен LLM). LLM подключается **только фолбэком**, и только
в одном месте: когда `parse_intent` вернул `ADD_TASK` с пустым `title`
(то есть правила не смогли выделить из сообщения ничего осмысленного).

## Условие срабатывания

```
parsed.intent is Intent.ADD_TASK and not parsed.title and ai_client is not None
```

`ai_client` берётся из `app/ai/client.py::get_ai_client()` — `None`, если
`openrouter_api_key` не задан в `.env` (тогда фолбэк тихо выключен, поведение
не отличается от чисто rule-based версии).

## Формат запроса

Оригинальный текст сообщения (не обрезанный правилами) отправляется в
OpenRouter (`app/ai/client.py::AIClient`) с системным промптом, требующим
строгий JSON:

```json
{"intent": "add_task|list_tasks|complete_task|delete_task|help",
 "title": "строка или null",
 "due_date": "YYYY-MM-DD или null"}
```

Ответ мапится в `ParsedIntent` (`app/conversation/ai_fallback.py`) и
подставляется вместо исходного результата парсера — дальше сообщение
обрабатывается тем же `ConversationEngine._dispatch`, что и rule-based
интенты (может оказаться, например, `list_tasks`, а не `add_task`).

## Обработка ошибок

Любая ошибка — сеть, таймаут, невалидный JSON, неизвестное значение
`intent` — перехватывается и превращается в `None`. Пользователь в этом
случае получает то же сообщение, что и без AI: «Не понял, какую задачу
добавить...». Фолбэк никогда не показывает пользователю техническую ошибку
и не роняет бота.

# Definition of Done

- каждый интент покрыт минимум 2 тест-кейсами;
- date_parser покрыт тест-кейсами на все поддерживаемые форматы и на "дата не найдена";
- ConversationEngine протестирован с замоканным TaskService;
- AI fallback покрыт тестами: успешный разбор, невалидный ответ, ошибка сети —
  без единого реального сетевого вызова к OpenRouter в тестах.
