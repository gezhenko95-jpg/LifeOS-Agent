# Finance Tracking Specification

---

# Цель

Учёт личных финансов через обычные сообщения боту — без отдельного
приложения, без синхронизации с банком. Раз в неделю — отчёт: сколько
"свободных" денег осталось в этом месяце и как расходы по категориям
соотносятся с нормой. Три решения приняты владельцем заранее (см.
HANDOFF), эта спека их не пересматривает, а раскладывает в конкретную
архитектуру:

1. Ввод — **свободным текстом в боте**, тем же парсером, что и задачи.
2. Категории — **фиксированный список в коде**, не пользовательская таблица.
3. Разбор — **считалка без LLM** (свободные деньги = доход − обязательные
   платежи; норма на категорию = процент от свободных), LLM только
   формулирует фразу поверх готовых чисел, с тихим фолбэком на сухой отчёт.

---

# Бизнес-требования

- пользователь пишет трату обычным сообщением («потратил 1200 на
  продукты», «такси 300») — бот распознаёт сумму и категорию, сохраняет;
- пользователь пишет доход («получил зарплату 80000», «доход 5000») —
  тоже сохраняется, отдельно от трат;
- раз в неделю — отчёт: доход за месяц, обязательные платежи, "свободные"
  деньги, по каждой (необязательной) категории — потрачено / норма;
- никакого ручного бюджетирования по категориям пользователем — нормы
  фиксированы в коде (см. «Категории» ниже), как и решено;
- сообщение о добавленной трате/доходе — короткое подтверждение суммы и
  категории, без разбора нормы внутри (это работа еженедельного отчёта,
  не каждого сообщения).

# Категории (фиксированы в коде, `app/finance/models.py`)

Один плоский список — деление на "обязательное" и "свободное" не
отдельное поле `kind`, а свойство самой категории (`MANDATORY_CATEGORIES`),
чтобы не заводить второе измерение поверх и без того фиксированного
списка:

```python
CATEGORIES = {
    "rent": "🏠 Аренда/ипотека",
    "utilities": "💡 Коммуналка",
    "subscriptions": "🔁 Подписки",
    "credit": "🏦 Кредит/рассрочка",
    "groceries": "🛒 Продукты",
    "transport": "🚕 Транспорт",
    "eating_out": "🍔 Кафе",
    "health": "💊 Здоровье",
    "entertainment": "🎉 Развлечения",
    "shopping": "🛍 Покупки",
    "other": "❓ Другое",
}

MANDATORY_CATEGORIES = {"rent", "utilities", "subscriptions", "credit"}

# Норма — процент от СВОБОДНЫХ денег (после вычета обязательных),
# только для категорий вне MANDATORY_CATEGORIES. Сумма = 100.
CATEGORY_NORM_PERCENT = {
    "groceries": 30,
    "transport": 15,
    "eating_out": 15,
    "health": 10,
    "entertainment": 15,
    "shopping": 10,
    "other": 5,
}
```

Свободные деньги за период = `sum(доход) − sum(траты по MANDATORY_CATEGORIES)`.
Норма категории = `свободные_деньги * CATEGORY_NORM_PERCENT[категория] / 100`.

# Модель данных (`app/finance/models.py`)

## Transaction

| Поле | Тип | Описание |
|---|---|---|
| id | int | первичный ключ |
| telegram_user_id | bigint | владелец |
| kind | str | `"income"` или `"expense"` |
| category | str, nullable | одна из `CATEGORIES`; `None` для `income` |
| amount | int | сумма в рублях, > 0 (копейки не считаем — сознательное упрощение, ADR-004) |
| note | str, nullable | остаток свободного текста после суммы/категории |
| occurred_at | datetime | когда произошло (по умолчанию — момент сообщения; дата из текста не разбирается в этой итерации) |
| created_at | datetime | когда фактически записано |

Без уникальных ограничений — трат в один день может быть много.
Индекс `(telegram_user_id, occurred_at)` — под выборку "за период",
тот же паттерн, что `TaskRepository.count_completed_between`.

# Разбор в чате (`app/conversation/`)

## Новый модуль `amount_parser.py` (по образцу `date_parser.py`)

```python
def extract_amount(text: str) -> tuple[Optional[int], str]:
    """Найти сумму ("1200", "1.5к", "2 тысячи", с необязательным
    "руб"/"р"/"₽" после) — вернуть (сумма в рублях или None, остаток
    текста без найденного числа), тот же контракт, что у extract_due_date."""
```

## Новые intent'ы (`intent.py`)

`Intent.ADD_EXPENSE`, `Intent.ADD_INCOME`. `ParsedIntent` — новые поля
`amount: Optional[int] = None`, `finance_category: Optional[str] = None`
(только для `ADD_EXPENSE`).

## `parser.py`

```python
_EXPENSE_KEYWORDS = ("потратил", "потратила", "купил", "купила", "заплатил", "оплатил")
_INCOME_KEYWORDS = ("получил", "получила", "зарплата", "заработал", "заработала", "доход")
_FINANCE_CATEGORY_KEYWORDS: tuple[tuple[str, str], ...] = (
    ("аренда", "rent"), ("ипотек", "rent"),
    ("коммунал", "utilities"), ("свет", "utilities"), ("вода", "utilities"),
    ("подписк", "subscriptions"),
    ("кредит", "credit"), ("рассрочк", "credit"),
    ("продукт", "groceries"), ("магазин", "groceries"),
    ("такси", "transport"), ("метро", "transport"), ("бензин", "transport"),
    ("кафе", "eating_out"), ("ресторан", "eating_out"), ("кофе", "eating_out"),
    ("аптек", "health"), ("врач", "health"), ("лекарств", "health"),
    ("кино", "entertainment"), ("подарок", "entertainment"),
    ("одежд", "shopping"),
)
```

Проверка — якорем на начало сообщения (`_starts_with_any`), тот же
приём, что у `_COMPLETE_KEYWORDS`/`_DELETE_KEYWORDS` (AUDIT.md B-6):
команда о трате/доходе почти всегда в начале. Место в waterfall — сразу
после `DELETE_TASK`, до `JOURNAL_ENTRY` (без коллизий по ключевым словам,
проверено вручную по всему списку существующих триггеров).

Категория для `ADD_EXPENSE` — первое совпадение из
`_FINANCE_CATEGORY_KEYWORDS` в остатке текста после вырезания
триггера и суммы; нет совпадения → `"other"`, не ошибка и не переспрос.

## `ConversationEngine`

Новый опциональный `finance_service: FinanceService | None = None` —
тот же паттерн опциональности, что у остальных пяти сервисов движка.
`_dispatch` получает две новые ветки:

- `ADD_EXPENSE`: `finance_service.add_transaction(uid, EXPENSE, amount,
  category=parsed.finance_category, note=...)`. Если `amount is None`
  (сумма не распозналась) — не ошибка молча, а явное «Не понял сумму.
  Напишите, например: «потратил 500 на такси»» (тот же приём, что у
  ADD_TASK с пустым title).
- `ADD_INCOME`: аналогично, `category=None`.

Обе ветки — награда через `_with_reward` (см. specs/016-engagement-
hooks.md): в отличие от `COMPLETE_TASK`/`HABIT_DONE`, здесь нет ветки
"не нашёл" — валидный `amount` всегда создаёт транзакцию, тот же уровень
структурной уверенности, что у `ADD_TASK`.

# Отчёт (`app/scheduler/finance_report.py`)

По образцу `weekly_digest.py`. Считает **за текущий календарный месяц**
(не скользящее окно в 7 дней — доход/аренда естественно месячные), но
**отправляется еженедельно** (воскресенье, как `send_weekly_digest_job`)
— промежуточная сверка внутри месяца, а не только раз в 30 дней.

```
Финансы за август 📊

Доход: 80 000 ₽
Обязательные платежи: 45 000 ₽
Свободно: 35 000 ₽

Продукты: 6 200 / 10 500 ₽ нормы
Транспорт: 1 800 / 5 250 ₽ нормы
...
⚠️ Кафе: 6 000 / 5 250 ₽ — сверх нормы
```

Категории без единой траты за месяц — не показываются (тот же принцип,
что у пустых секций брифинга/дайджеста). Если `ai_client` доступен —
одна короткая AI-фраза поверх готового текста, тем же паттерном
(`_generate_insight`), тихий fallback на сухой отчёт при сбое AI.

`send_finance_report_job` в `app/telegram/jobs.py`, регистрация в
`bot.py` — новые настройки `finance_report_enabled` (default `True`),
`finance_report_hour`/`_minute` (default как у `weekly_digest`: 20:00).

# Что НЕ входит в эту итерацию

- REST API (`app/api/finance.py`) и карточка на `/ui` — сознательно
  отложено: сначала посмотреть, приживётся ли ввод текстом вообще (тот
  же урок, что и с engagement hooks — задачи/цели через `/ui` не
  прижились). Добавить дёшево через тот же `container.py`-паттерн, когда
  понадобится.
- Разбор даты в сообщении о трате («вчера потратил…») — `occurred_at`
  всегда "сейчас". Дешёвый v2 через уже существующий `extract_due_date`.
- Автообнаружение периодических обязательных платежей (аренда каждый
  месяц без повторного ввода) — пользователь пишет каждый раз заново,
  как и с задачами без recurrence. Если станет неудобно — `recurrence`
  по образцу `Task`, отдельная спека.
- Мультивалютность, копейки, курсы — рубли, целые числа.
- Изменение/удаление транзакции через чат (только через возможное
  будущее REST API) — на v1 ошибся суммой, значит следующее сообщение
  подправит картину за месяц не сильно, специально чинить не стали.

# Definition of Done

- `extract_amount` покрыт тестами: целое число, дробное («1200.50»),
  множитель «к»/«тысяч», с «руб»/«₽»/без, отсутствие числа → `None`.
- `parse_intent` — `ADD_EXPENSE`/`ADD_INCOME` распознаются, категория
  определяется по ключевому слову и падает на `"other"` без совпадения,
  не путаются с `COMPLETE_TASK`/`WATCHLIST`/остальными триггерами.
- `FinanceService.add_transaction` / `list_transactions_since` /
  `build_period_summary` покрыты unit-тестами (свободные деньги,
  норма, сверх нормы, пустой период).
- `ConversationEngine` с `finance_service=None` работает как раньше
  (тест на обратную совместимость, как у rewards_service).
- `build_finance_report` покрыт как `build_weekly_digest`: пусто/
  непусто, AI-фраза успех/ошибка/выключен, категория сверх нормы.
- Миграция `018_create_transactions` — `upgrade`/`downgrade` прогнаны.
- Все тесты (886 на момент написания + новые) зелёные, ruff/black чисты.
