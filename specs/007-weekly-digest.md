# Weekly Digest Specification

---

# Цель

Раз в неделю (воскресенье вечером) пользователь получает короткую сводку:
сколько задач выполнено, как обстоят дела с привычками (стрики) и
целями (текущий прогресс) — плюс, если доступен AI, одна короткая фраза-
инсайт по итогам недели, и картинка-график (см. ниже). Не дублирует
утренний брифинг (тот — про сегодня, дайджест — про прошедшую неделю).

---

# Что НЕ входит

- Снапшоты истории прогресса целей — показывается только ТЕКУЩИЙ
  прогресс, без дельты за неделю (ADR-004: не усложняем ради этого схему
  БД).
- Учёт привычек, отмеченных, но затем удалённых за неделю — считаются
  только актуальные (активные) привычки на момент отправки.

---

# Данные

Требует `Task.completed_at` (см. migration
`009_add_recurrence_and_completed_at_to_tasks.py`) — раньше у задачи не
было отметки времени завершения, посчитать "выполнено за неделю" было
нечем.

`TaskRepository.count_completed_since(telegram_user_id, since) -> int` —
считает `status == "completed" and completed_at >= since`.

---

# Сборка текста (`app/scheduler/weekly_digest.py::build_weekly_digest`)

По образцу `app/scheduler/briefing.py`:

1. `task_service.count_tasks_completed_since(uid, неделя назад)` →
   секция "Выполнено задач за неделю: N задач." (с корректным
   склонением: задача/задачи/задач; ноль → отдельная фраза "ни одна
   задача не была отмечена выполненной").
2. `habit_service.list_active_habits` + `get_streak` на каждую → секция
   "Привычки:" (пропускается, если привычек нет).
3. `goal_service.list_active_goals` → секция "Цели:" с текущим
   прогрессом (пропускается, если целей нет).
4. Если передан `ai_client` — одна короткая AI-фраза (≤25 слов) поверх
   собранного текста, тем же паттерном, что `_generate_insight` в
   `briefing.py`. Любая ошибка AI — тихо пропускается, дайджест всё
   равно уходит.

# Графики (`app/scheduler/charts.py`)

Настоящая картинка (matplotlib, backend `Agg` — без дисплея, обязательно
для Docker), а не текстовые псевдографики. Строится только из УЖЕ
существующих данных (без снапшотов истории прогресса целей — см. "Что НЕ
входит"):

- столбчатый график "выполнено задач по неделям" — последние 6 недель,
  через новый `TaskService.count_tasks_completed_between(uid, since,
  until)` (полуоткрытый интервал `[since, until)`, по одному вызову на
  неделю);
- тепловая карта привычек за 30 дней (одна строка на активную привычку,
  зелёная клетка = отмечена в этот день) — через новый
  `HabitService.get_completed_days(habit_id, since) -> set[date]`.

Оба графика — в одной картинке (два subplot друг под другом), чтобы
дайджест оставался одним сообщением: `context.bot.send_photo(chat_id,
photo=chart, caption=text)`. Если подпись длиннее лимита Telegram (1024
символа) — фото без подписи + текст отдельным сообщением.

`render_chart` возвращает `None`, если показывать нечего (0 активных
привычек И 0 выполненных задач за все 6 недель) — тогда дайджест уходит
просто текстом, как раньше. Генерация графика обёрнута в `try/except` в
`send_weekly_digest_job` — сбой рендера (например, из-за шрифтов) не
должен срывать отправку текста дайджеста, тот же принцип, что и у
AI-инсайтов везде в проекте.

Разделение: `gather_chart_data` (ходит в сервисы, тестируется с
замоканными сервисами) / `render_chart` (чистая функция без БД,
тестируется без моков — на входе данные, на выходе PNG-байты или
`None`).

# Планировщик

`send_weekly_digest_job` (`app/telegram/jobs.py`) — по образцу
`send_morning_briefing_job`. Регистрируется в `app/telegram/bot.py` через
`run_daily(..., days=(6,))` — воскресенье (PTB: `0=понедельник,
6=воскресенье`, как `date.weekday()`). Настройки: `weekly_digest_enabled`,
`weekly_digest_hour` (20 по умолчанию), `weekly_digest_minute` (0).

---

# Definition of Done

- `count_completed_since` покрыт интеграционным тестом на SQLite
  in-memory (период, изоляция по пользователю, "ничего не выполнено");
- `build_weekly_digest` покрыт как `build_morning_briefing`: пустой/
  непустой список задач (включая склонение числительного), наличие/
  отсутствие привычек и целей, AI-инсайт (успех/ошибка/выключен);
- `render_chart`/`gather_chart_data` покрыты: есть активность → PNG,
  совсем пусто → `None`, один элемент/много привычек — не падает.
